# P1.4.1 scanner — 2026-10-19

The scanner uses handle-based directory enumeration for size, timestamps,
attributes and 128-bit file identities. It opens files relative to a pinned
root, rejects descendant reparse traversal, checks the root identity before
and after the walk, and rejects reuse of an index after root replacement.
Failed/incomplete subtrees preserve existing records without false deletions.
Internal metadata/temp files and ignored trees are pruned. Reparse and invalid
local names are unsyncable metadata with no signed record or traversal.

Changed files use the one-pass hasher and are deferred on detected concurrent
changes or I/O failure. Unchanged metadata avoids hashing; directory child-mtime
changes alone do not publish directory versions. Verified file-ID rename
candidates reuse their signed chunk lists, with a checked current handle;
missing published RW paths become signed tombstones. RW changes increment the
device vector and use the exact signed-record envelope. RO scans track actual
local edits/deletions without signing or advancing vectors. Remote application
must serialize with scans through the upcoming folder scheduler.

Scan start/completion/defer/enumeration-failure/failure events share a session
ID. Completion includes numeric work totals; failures include native errors
and HResults where available. The journal excludes filenames, contents, keys
and record bodies. Relative-path problems are returned for local presentation.

The real 100,000-file benchmark uses one-byte files in 100 directories and a
fresh database, with full initial hashing/signing/chunk indexing. The warm SSD
rescan visited all **100,100 rows in 0.6387915 seconds**, hashed **zero** files,
wrote **zero** records and preserved the sequence. Initial indexing took
**6.6744746 seconds**. This is local Windows x64, warm filesystem cache;
there is no cold-cache, network-share, Arm64-runtime or physical-server claim.
Raw output: `artifacts/p1-scanner-benchmark-indexed.log`; retained corpus:
`artifacts/scan-100k-20261019/tree`; its successful fresh index is
`index-0c4627c2688f4b20919c5590201a3972.db` in that corpus's parent.

The first run exposed quadratic chunk replacement: deleting by path scanned
the hash-keyed chunk table for every file. It was stopped and its partial
database retained. Additive schema migration 2 adds `chunks(path_key)` through
the existing backup/transaction migration runner. A regression opens a v1
database, verifies the backup/version upgrade, and checks SQLite's query plan
uses the path index without a table scan. No old migration was rewritten.

Focused local checks pass 27 Engine, 25 Storage and 123 Core cases. They cover
same-size/mtime file replacement, signed rename/deletion, ignore transitions,
directory timestamp stability, invalid/reparse paths, exclusive file/directory
locks, failed-subtree preservation, root replacement at start and during a
walk, cancellation, RO changes and diagnostic redaction. The mid-read overwrite
test waits for a distinct system-clock tick to avoid a timestamp-resolution
collision. Metadata checks with shared writers remain detection, not an atomic
snapshot, as documented in the source design.

Scoped Core/Engine/Storage analyzers are clean.
The canonical local runner passed all 195 cases, native probes, diagnostics,
watcher recovery and publishing in 110.88 seconds with fuzz explicitly skipped.
The final unsyncable-removal adjustment then passed all 27 Engine cases again.
