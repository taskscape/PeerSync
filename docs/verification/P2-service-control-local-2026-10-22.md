# P2 service control and folder API local verification

The installed service control slice now supports adding and joining folders, listing folders and peers, reading the local index, retrieving share keys through an audited RPC, and reporting service status/events over the verified named pipe. `psp add` prints the new share key through `GetFolderKeys`; `psp share <folder>` retrieves it again. The caller SID is recorded by the state-store audit path, and debug events never contain the key or path. Folder startup verifies `.psp/id`, registers a live scan schedule, and exposes the folder to peer authentication and discovery. A service started without folders keeps supervising components added later.

The control host sets a 15-second `HostOptions.ShutdownTimeout`. The loopback service test measures disposal with an active authenticated peer session and asserts the two hosts drain within 15 seconds. This validates runtime drain behavior in the local process; it does not substitute for an installed SCM stop test.

The latest canonical local command was `./build/Verify.ps1` on `win-x64`. It passed with zero build warnings/errors in 692.527 seconds. All 1,686 unit tests and 14 real-engine simulation cases passed with no skips or failures. The five-target fuzz run lasted 600.000 seconds, processed 187,190 seeds, and reported zero crashes. Native probes, diagnostics checks, and deployment publishing checks passed. `artifacts/verification-win-x64.json` reports `status=passed`, `runtimeChecks=true`, `phase=P1`, and `gateP1Passed=false`; it does not certify Gate P2 or hosted CI. The service suite includes generated-clock skew rejection and reconnect recovery through two installed-host loopback runtimes; see [installed clock loopback verification](P2-installed-clock-local-2026-10-22.md) and the [native SCM verification](P2-installed-scm-local-2026-10-22.md).

The same run includes authenticated QUIC live index notifications, the multi-peer block scheduler, adaptive per-peer byte windows, bounded concurrent chunk prefetch, 64-hash QUIC batches, bounded endgame duplicate requests, cross-endpoint diagnostic correlation, and device-wide upload/download rate limits. Index notifications coalesce to the newest published sequence; receivers use the existing resumable signed-page exchange and clock admission. Per-peer windows start at 4 MiB, grow additively to 32 MiB after successful service, and halve after transport/congestion failures; peer `NotFound` and `Forbidden` responses release capacity without shrinking the window. Each assembly prefetches in bounded 32 MiB groups, sends at most 64 missing hashes per request, retains verified successes when another block in a batch is unavailable, and writes chunks in file order. The final remote batch is requested concurrently from two authenticated peers; the first fully verified response wins and cancels/drains the duplicate. Block authorization checks ordinary indexed chunks and complete active directory-graph references under the current ignore policy, with a 4,096-candidate bound and correlated `NotFound`, `Forbidden`, and unavailable diagnostics that omit content hashes and paths. Focused tests verify bidirectional QUIC notifications, push-triggered page exchange, local index notification, 64+1 batching for 65 chunks, partial-batch retention, two-block QUIC batch exchange, final-chunk peer racing and loser cancellation, concurrent prefetch, resume reuse, hash and length rejection, cancellation, adaptive window behavior, peer rotation/failover, shared QUIC session IDs, and throttling through large blocks and installed folder engines. Download limiter events carry the shared session ID; upload limiter events can currently be correlated by timestamp with the server's block-stream event. The canonical probes use local harnesses and produced no Windows Firewall prompt; physical LAN throughput remains open.
