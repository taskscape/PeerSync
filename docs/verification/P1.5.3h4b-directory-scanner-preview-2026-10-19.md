# Local-source scanner staging preview

The internal scanner snapshot integration gate is disabled in production.
It must be removed only after incoming-directory/subtree integration and full
acceptance pass. This checkpoint exercises real native scans with that gate
enabled; it does not claim deployed service or connected subtree convergence.

Files and tombstones commit first. Supported directory observations stage
private signed templates, retaining prior advertised rows and their native
mtime. Direct child-key inventories include new unsigned supported children,
so incomplete publication cannot silently omit them. Stable native/template
inputs retain the queue version, time and vector across scans. A compact cache
can skip unchanged validated inputs. The bounded worker publishes child roots
before parents, without repeating a native tree walk for each capture batch.

Complete-walk reconciliation reads paused/backed-off work through bounded
path-only pages. It atomically discards obsolete queue/draft metadata after
absence, type change, exclusion, loss of write authority or replacement of
the expected signed row. Uncertain enumeration/case namespaces pause work;
a subsequent complete observation can resume the exact template. Native
bytes and signed rows are never deleted by reconciliation. An uncached
incoming authenticated snapshot is deferred for graph/materialization proof;
not-yet-applied children cannot be signed away as a local deletion. Existing
readonly unsigned-edit behavior remains active.

Debug events distinguish staged, retained, paused, discarded, cached and
incoming-proof-pending observations. Queue versions correlate scanner and
worker/publication events across restart. Logs use fixed codes/counts and
native error numbers, without paths, payloads or credentials.

A new interrupted-walk regression initially failed: a newly staged directory
had no published row from which to retain its mtime. Its native timestamp
settled after the first walk, replacing an otherwise identical private queue.
The planner now retains the pending template's mtime when native identity,
attributes, spelling and expected prior sequence match. The test explicitly
changes native mtime, fails enumeration, verifies pause and resumes the same
queue after a complete walk. It also checks diagnostic correlation/redaction
and zero dropped events.

Validation:

- All 253 Storage cases pass locally, 5.47 seconds, exit 0. New reconciliation
  coverage checks paused/backed-off path pages, stale-version rejection,
  atomic queue/draft rollback at a SQL failure and independent-row retention.
- All 50 focused capture/scanner/worker cases pass on the final changes,
  6.24 seconds, exit 0. Checks include new/nested native trees, file-first
  publication, finite no-op/content-only convergence without mtime feedback,
  stable restaging/input reset, external rename, exclusion, readonly scans,
  replaced incoming sources, incomplete walk resume, input mutation before
  key binding, and interruption immediately after atomic publication.
- The broader Engine checkpoint before the final logging/three additional
  focused cases contains 831 cases: 826 pass, five fail, zero skipped,
  29.18 seconds, exit 2. Exactly the retained four flat/nested directory case
  arrival-order variants and the file-wins-directory case fail. This is not
  a full-suite pass. The final focused run covers the later changes.
- Compiler/configured-analyzer checks are clean in both production and test
  projects, without load warnings or truncation. No canonical/CI/main or
  clean-machine acceptance is claimed. No additional GitHub run was started.
