# P1.5.5c2c clock status UI (local checkpoint)

The app now opens a WPF clock-status window and uses the fixed installed-service
client. Production provides no fixture pipe, owner or process override. A single
cancellable controller queries status, watches updates and reconnects after
failure or clean stream completion. It uses a 15-second idle deadline, cancels
and drains a pending read before enumerator disposal, and retries from one to
30 seconds. Each reconnect creates a fresh client and installed-service lookup.

UI updates run through the dispatcher. A new attempt clears stale rows and binds
its first service epoch; later updates must retain the epoch and increase sequence.
Old generations, old sequences and updates after a failed attempt cannot restore
success. The view shows signed minutes (peer UTC minus local UTC), typed reasons,
peer connection state, missing/invalid samples, empty and truncated snapshots,
and explicit production availability. A fresh accepted sample clears skew.

App logs live under `%LOCALAPPDATA%\PeerSync\logs\app\<run-id>`; the status-only
service uses `%ProgramData%\PeerSync\logs\service\<run-id>`. They retain the
existing journal rotation/privacy limits. App connection attempts have correlated
session IDs and bounded snapshot counts. Failures retain RPC status, HRESULT and
true native errors through at most eight sanitized nested causes, including gRPC
debug exceptions. No raw messages, paths, SIDs, peer IDs or keys are serialized.

All 13 App cases pass. Six row cases cover signs/reasons; generation/epoch/sequence,
empty/truncated/recovery and controller tests cover replay rejection, clean-end
reconnect, disposal/cancellation, idle timeout and capped backoff. An actual native
pipe with the wrong server PID produces an identity verification UI reason and
sanitized RpcException/SecurityException diagnostic causes without identity/path
leaks. This complements the native client owner/PID checks and eight host cases.

Two rendering tests run actual WPF windows on STA dispatchers. The end-to-end
case uses two actual NTFS/SQLite TransportFolders, real clock rejection/recovery,
runtime registration, real named-pipe gRPC, verified fixture owner/PID and the
same controller/window used by production. Rendered controls show +11.00 minutes,
then accepted/connected, then no stale success after host shutdown. Separate
typed snapshots render negative offsets, missing/invalid samples and truncation.
The windows are off-screen fixtures; these are actual WPF renders, not screenshots
of a deployed installation. Eight PNGs are retained in `artifacts/clock-ui/` and
uploaded by x64 CI. Header pixels and actual rendered control text are checked;
the images were visually inspected. Apparent gaps in repeated image displays
were checked against the complete saved pixels; no product defect was inferred.

Scoped App/App.Tests/Contracts/Service compiler and configured analyzer checks
are clean without truncation or workspace-load warnings. Evidence is in
`artifacts/p1-clock-ui-{restore,build,tests-build,tests,render}.log`,
`artifacts/tests/clock-ui/` and `artifacts/clock-ui/`. Final canonical
`build/Verify.ps1 -SkipFuzz` passes all 1,166 cases and native/probe/watcher/QUIC/
publication checks in 139.5608119 seconds, terminal exit 0, Engine included.
Counts: 134 Core, 15 Crypto, seven Protocol, nine Net, 720 Engine, 218 Storage,
39 Contracts, eight Service, 13 App and three Simulation methods (eight property
