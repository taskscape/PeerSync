# P1.5.3 verified chunk assembly — 2026-10-19

`ChunkAssembler` writes only into a caller-owned temporary stream. It accepts
an already verified immutable `VersionView`, rechecks existing temporary chunks,
then tries local chunk-index hints before asking the transport callback for
missing data. Local reads use the pinned root/no-reparse primitives. Stale,
missing, changed or inaccessible candidates fall back; at most 64 candidates
are tried per chunk. Actual bytes, not the index, determine integrity.

Network bytes must have exactly the signed chunk length. Copy them into an
owned pooled buffer before BLAKE3 verification and writing. Memory is bounded
by one protocol-validated chunk. The whole-file BLAKE3 and byte count gate
success independently, including empty files. Only after that check are extra
temporary bytes truncated and the stream flushed. Installation must still
flush a real file to disk before mutation; `FlushAsync` alone does not claim
power-loss durability. Exceptions/cancellation never publish an index row or
install a target; partial verified temporary bytes remain reusable.

Debug events distinguish verified temporary/local reuse and verified remote
chunks, plus start/completion/failure. A session ID joins counts, elapsed time
and exception/HRESULT codes. Paths, keys, hashes and content are not logged.
The host owns tree/index/journal lifetimes and serializes the destination.

Eight added test cases cover mixed temporary/local/network assembly and
truncation, corrupted/missing local hints and a later intact candidate, reparse
candidate rejection, bad remote length/hash before writing, independent whole
hash failure and subsequent resume, cancellation after an uncooperative fetch,
empty-file integrity and diagnostic redaction. All 92 Engine cases pass.
Scoped Engine/Engine.Tests compiler/analyzer checks are clean, without workspace
load warnings or truncation. The canonical local runner passed 260 cases,
native probes, diagnostics, watcher recovery and probe publishing in 112.15
seconds, exit 0, with fuzz explicitly skipped. Evidence:
`artifacts/p1-assembly-tests.log`, `artifacts/p1-assembly-verification.log`.

This does not complete P1.5.3. The transport callback still needs the planned
transport abstraction/protocol integration. Priority scheduling, final target
comparison, permissions/timestamps, durable apply/recovery, archive accounting
and retry integration remain to be implemented. The task stays unchecked.
