# P1.5.1/P1.5.2 verified selection foundation — 2026-10-19

`VersionView` verifies the exact folder-bound signed envelope before parsing,
then checks version metadata, authors/vectors and file/chunk layout. It owns
immutable data and exports parsed-body clones. The resolver removes causally
dominated candidates before deterministic selection, max-merges vectors without
incrementing an edit counter, and preserves unknown fields when RW peers sign
a merged body. RO peers forward the original body/signature unchanged, with
their merged causal knowledge stored only in local metadata.

The source design's live mtime rule supersedes the draft checklist example's
blanket changed_ticks comparison. Tombstones use signed deletion time; ties use
full DeviceId, then exact body bytes. This avoids favoring an old offline file
only because a scan noticed it later. Matching content still chooses stable
metadata. Loser fate follows archive size/keep-both settings. Pure conflict-name
helpers preserve directories/extensions, format UTC time/device codes, accept
collision suffixes and bound Unicode names without splitting surrogate pairs.
Exhausted path budgets fail before filesystem replacement. These helpers do not
reserve files or claim that conflict data has already been preserved.

`NeededSet` computes affected paths from current local/all-remote records.
Remote rows, sender cursor and needed changes commit in one writer transaction.
Invalid signatures/layouts/duplicate paths, callback failures and observed
cancellation cannot partially advance the index. Replays are idempotent,
sequence gaps are allowed for unpublished local rows, and cursor mismatches
fail. Peer approval/name metadata survives cursor updates; network admission
and clock-skew enforcement remain caller responsibilities. Migration 3 adds
`remote_files(path_key)` for efficient per-path queries across devices.

Ignored/unsyncable/pending-rescan local paths are withheld from application.
RO unsigned local changes remain needed but blocked unless overwrite is enabled;
an exact match can adopt the signed metadata without rewriting data. Logical
RO vector merges never forge or replace the original forwarded signature.
Local/settings changes can recompute affected paths or rebuild the needed set.
The upcoming folder engine must serialize filesystem apply/scans and recompute
needed paths after local commits. Sender index-generation/reset negotiation is
P2 protocol work; this cursor API does not claim to solve database resets.

Correlated receive/replay/failure diagnostics expose counts, timing and reason
codes without paths, content, record bytes or keys. Current focused checks pass
**80 Engine cases** and **25 Storage cases**. They include all candidate-order
permutations, causality versus timestamp, edits versus deletions, deterministic
RW signatures/unknown fields, RO forwarding/merge convergence, archive policy,
invalid metadata, atomic rollback/cancellation, independent concurrent receives,
approval preservation, replay/gaps, exclusion policies and naming bounds.
SQLite query-plan tests verify both chunk-path and remote-path indexes, with
backups before each step of the v1 → v2 → v3 migration.

The canonical local runner passed **244 cases**, native probes, diagnostics,
watcher recovery and publishing in **103.73 seconds**, with fuzz explicitly
skipped. The final receive-logging and naming changes then passed all 80 Engine
cases. Evidence: `artifacts/p1-needed-verification.log`,
`artifacts/p1-needed-tests.log`, `artifacts/p1-needed-storage-tests.log`.

This is an implementation foundation, not a completed filesystem sync engine.
Actual case-clash preservation, unknown directory children, atomic file apply,
archive persistence/pruning, clock-guard integration and simulation remain to
be implemented/tested. P1.5.2's entire conflict-table acceptance is therefore
still incomplete. Both tasks remain WIP and unchecked; required CI is also
[blocked by GitHub Actions billing](https://github.com/taskscape/PeerSync/issues/10).
