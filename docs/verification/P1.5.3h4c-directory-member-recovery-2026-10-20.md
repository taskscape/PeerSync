# Durable subtree member installation and recovery

P1.5.3h4c remains WIP. The native path now copies authenticated directory and
file descendants, with source/root/member-bound durable progress and recovery.
Installation coverage does not complete a source. Whole-tree publication proof,
incoming-copy namespace protection, stale-ledger retirement, gossip/late-page
integration and production scanner activation remain open. All five connected
subtree preservation baselines are still mandatory and failing.

Schema 28 adds per-source/destination-root-native-ID installation cursors and
original graph-link/member-source-ID/type/destination/native-ID rows. FULL
reservation admits only the exact next canonical graph member and its kind-9
intent together. FULL accounting installs the verified native ID, advances
the cursor and removes the intent atomically. Exhaustion cannot skip a remaining
graph member or clear the original case barrier. Root reselection retains old
trees and old identity-bound witnesses rather than overwriting them.

Kind 9 stores bounded physical/source/root/member identities, metadata link,
projected destination, sibling GUID temporary/native ID and preparation state.
Recovery reauthenticates original envelopes from the retained graph, checks
source/root/snapshot/cursor/ledger binding and rejects malformed flags, links,
destinations and trailing bytes. It does not duplicate large root and member
signed bodies into one intent.

The worker creates parents before children, pins the copied root and each
intermediate parent by its installed native identity, and retains one new
component handle at a time. Files use original authenticated chunks and whole
hash verification. Prepared native objects install by no-overwrite handle move;
the Held file remains independent. Recovery of visible files uses a guard that
excludes data writers, rather than a directory classification handle. Known
installed directory identity does not authorize overwriting unknown children.

Native work defaults to 32 directory-case units per pass, shared across root
creation/member installation; graph work retains its separate 1000-unit bound.
Failures conservatively consume offered work, successful prefixes remain durable,
and earlier installed members still request scanning after a later I/O deferral.
Unavailable data and exhausted copies awaiting publication use persistent backoff.

Unknown occupants and replaced ancestors preserve the earlier partial tree and
select another root identity/slot. Edited prepared staging and unproven nonempty
unprepared file staging remain protected. File Hidden metadata is prepared
before rename so crash replay does not accidentally expose a hidden-temporary
attribute as copied metadata; ReadOnly is applied after moving writable staging.
Diagnostics correlate member reservation, preparation, installation, accounting,
protected parking, root reselection and replay. SQL failures retain their intent
and expose extended error 1811 without paths, payloads, keys or SQL text.

## Validation

- All 259 Storage cases pass locally, 5.38 seconds, exit 0. Five new cases cover
  durable reopen/frozen reads, three SQL accounting rollback boundaries, strict
  next-member/exhaustion guards, active-intent root-reset rejection and retention
  of old identity-bound witnesses. Schema/backup assertions and legacy downgrade
  fixtures now include version 28.
- All 105 focused native Engine cases pass, 9.37 seconds, exit 0. Twenty-three
  new cases cover bounded nested RW/RO copying, ten file/directory crash boundary
  variants with database reopen, accounting failure/replay/redacted diagnostics,
  member collision/root reselection, protected edited staging, replaced parent
  identity, recovery collisions, remote-root advertiser failover, existing data
  writer exclusion, graph binding and malformed journal rejection.
- The simulated empty receiver uses a second NTFS root/index on this host. It
  starts without the original subtree, fetches authenticated metadata and file
  chunks, fails its preferred route, and succeeds only through another current
  advertiser of the exact root envelope. The winner's different envelope is not
  accepted as an alternative route. Original member source IDs are retained;
  forwarding identity never becomes subtree ownership. This is not physical
  multi-machine or alternate-Windows-version validation.
- The first broad run exposed four fixture failures: v6/v8 synthetic downgrades
  left new member tables in place, causing migration-28 table-exists errors.
  Correcting those fixture schemas resolves all four. The complete rerun has
  889 cases: 884 pass, five fail, zero skipped, 27.78 seconds, exit 2. Its failures
  are exactly the four flat/nested directory arrival-order variants and the
  file-wins-directory case. This is not a full-suite success claim.
- The initial edit-staging fixture also hit Windows hidden-file create/truncate
  restrictions. Opening that existing hidden temporary for writing exercises
  the intended real edit; recovery protects its bytes and copies from the
  authenticated source instead.
- Scoped compiler/configured-analyzer checks are clean in Engine, Storage and
  both test projects, without workspace load warnings or truncation. Static
  impact inspection covered FileApplier, FolderIndex and DirectoryLease; broad
  test/reference sections were bounded/truncated, followed by inspection of
  the exact journal, graph, staging and native-handle call sites. Runtime tests
  supply the separate filesystem/durability evidence.
- No canonical acceptance, new GitHub CI run, feature PR or merge was attempted.
  The source remains pending after all descendants install, until the remaining
  full subtree/publication/retention criteria are met.
