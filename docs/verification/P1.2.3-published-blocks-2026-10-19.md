# Immutable published content — 2026-10-19

Live file records previously described mutable user files. A later write or
delete could erase the advertised bytes before another peer fetched them.
`PublishedBlocks` retains independent BLAKE3-addressed chunks under
`.psp/blocks/<two hex characters>/<hash>` before a live record is published.
The scanner copies each exclusively owned chunk buffer during its existing
single hashing pass. It still checks source metadata/identity before and after
reading, and does not publish detected in-flight mutations. Failed captures can
leave verified unreferenced chunks, not a successful version.

Root-relative no-reparse directory leases create GUID staging files exclusively,
flush data, install without overwrite, and flush again. Existing entries must
have the expected length/hash and one hardlink. Reads use shared reader guards
that exclude other writers/deleters without requesting DELETE themselves.
The hardlink check uses Windows
[FILE_STANDARD_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info).
Unknown/corrupt/hardlinked/reparse entries are preserved and fail visibly.
Only exclusively created staging objects are eligible for cleanup after a
failed operation. Returned buffers are independent; no user-file hardlinks or
mutable transport buffers become retained storage. Per-instance bounded lock
stripes deduplicate concurrent captures. Callers finish operations before
disposing the store.

Migration 5 adds `content_ready`, default false. Existing databases are backed
up by the normal migration runner. `ReadIndexBatch` withholds uncaptured live
files while safely advancing cursors over gaps; directories/tombstones need no
content. A successful backfill writes a fresh publication sequence while
preserving the original signature/body/edit vector. Ordinary unchanged scans
then retain the no-hash path. RO local edits remain unpublished/uncaptured.
Readiness records successful capture, not immunity to subsequent disk loss or
external corruption; serving always rechecks actual bytes.

The assembler tries verified published blocks before mutable chunk-index hints
and network fetches, and captures verified resumed/local/network chunks. Apply
completion and recovery capture the final verified file before committing its
live record/readiness. Metadata-only/legacy completion follows the same rule.
The diagnostic event `assembly.published_reused` distinguishes immutable reuse;
scanner cache hash failures return/log `published-content-verification-failed`.
No filenames, hashes, chunks, signed bodies or folder keys are logged.
