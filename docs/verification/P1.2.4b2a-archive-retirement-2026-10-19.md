# Durable archive policy retirement — 2026-10-19

An absent archive row/file is not evidence that retention policy authorized its
removal. Migration 8 adds archive retirement witnesses containing the exact
archive row, root/file identity, hash/size, policy reason, preparation time and
optional completion time. A partial unique index allows one pending witness
per archive ID; completed witnesses do not obstruct SQLite ID reuse.

Pruning verifies an independent regular file under its mutation guard and
FULL-durably reserves a witness before requesting native deletion. It proves
the target absent before a second FULL transaction atomically removes the
unchanged archive row and completes the witness. Row/root mismatches and
pending application reject reservation; changed rows reject completion.
Submission owns its arrays. Completion replay cannot remove a reused row ID.

Recovery runs under the shared folder gate after root/application checks and
before the persisted daily schedule. It resumes only the recorded file identity
with matching hash/length, or completes an already absent prepared target.
Changed/replaced/linked/locked/reparse objects and concurrent replacements stay
untouched, with the pending witness and row available for attention/retry.
Missing unprepared archives still reconcile ordinary accounting, without
creating a completed policy witness. Read-only archives remain prunable through
the existing guarded metadata/deletion path.

Preparation/completion failures retain the appropriate recovery state. A real
SQLite trigger proves that row removal rolls back if witness completion fails.
Cancellation between preparation and deletion keeps the file; cancellation or
failure after native deletion leaves the witness pending for restart completion.
Expiry and capacity reasons are separate. Events correlate preparation and
recovery by the stable witness GUID and exclude paths, hashes, file contents
and SQL/exception text; the existing journal reports native/SQLite codes and
bounded retry metadata.
