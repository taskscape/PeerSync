# P1.1.1 folder keys and text — 2026-10-19

Implemented RW, RO and encrypted-peer capabilities, HKDF-SHA256 domain
separation, Ed25519 signing and verification, FolderId, and canonical
RFC 4648 Base32 text with CRC-10/ATM. Lengths are 55/106/55 characters.
Case, whitespace and dashes normalize before validation; nonzero unused
Base32 bits are rejected. Errors and string/JSON diagnostics omit key material.
Key objects own their private buffers, clear them on disposal, and expose
copies only through explicit key export properties/methods. The decoded
text buffer must be disposed after import. Returned secret copies and exported
strings remain the caller's responsibility; immutable .NET strings cannot
be reliably erased.

Three public synthetic fixtures (zero, ascending, descending) were generated
using Python hmac/hashlib and PyCA cryptography 50.0.2/OpenSSL Ed25519,
independently of the production NSec/libsodium implementation. The CRC
reference uses polynomial long division, independently of the production
byte recurrence. Regenerate with `build/Generate-FolderKeyVectors.py` in
an isolated Python environment with `cryptography==50.0.2`; ordinary .NET
builds and tests read the checked-in JSON without Python.

Local evidence:

- Release solution build: zero errors or warnings.
- Core: 9 passing cases; Crypto: 10 passing cases; zero skipped.
- Every different Base32-symbol replacement at every position in all nine
  fixture texts is rejected, including prefix and checksum positions.
  Single-symbol insertions/deletions and nonzero padding aliases are rejected.
- Independent public key, content/auth/RO-auth key, FolderId, deterministic
  signature and all text exports match each vector.
- RO/F verification succeeds; signing and stronger capability exports fail.
  Message/signature mutations and foreign-folder signatures are rejected.
- Defensive-copy, normalization, redaction and disposal checks pass.
- Scoped Roslyn Core/Crypto analyzer checks: zero warnings/errors,
  no workspace-load warnings, no truncation.
