# Recoverable file/directory transitions — 2026-10-19

`FileApplier` now stages and installs both node kinds for type transitions.
Directory-only metadata/deletion remains `DirectoryApplier`'s responsibility.
A winning directory retains the old file using the existing archive/oversize/
keep-both policy, then installs an owned empty directory. A winning file moves
the whole old directory to a no-overwrite public conflict sibling, including
unknown children, without enumerating, following or recursively deleting them.
Directory trees are never represented as single-file archive entries. The same
preservation applies to signed deletions with the opposite kind and local
archive restoration over an existing directory.

Existing bounded kind-1 signed and kind-2 local-restore intents retain their
format. Desired kind comes from the authenticated record; original kind comes
from bound native attributes/identity. Directory originals have logical length
zero and no file hash. Validation prevents directory retention in the private
file archive. Empty staging directories are exclusive GUID siblings; persisted
root/node identities govern reopening and file/directory staging use separate
reuse keys. Classification guards are never used as file-content guards: files
are reopened with write sharing excluded before verification/mutation.

FULL-durable preparation precedes moving the old node. Atomic no-overwrite
installation follows the user-approved brief missing-target interval. Recovery
before scanning completes matching staging/installed objects or restores the
whole retained object when staging is missing. Unknown targets are preserved
and deferred; changed root/temporary/retained identities fail visibly with the
intent retained. Children written while preparing a directory move travel with
the same directory. Cancellation does not abandon destructive preparation.

Completion/deferred completion after moving a directory use new FULL-durable
storage operations. They account for the root result, mark live former
descendants NeedsRescan, remove existing descendant needed work, and remove the
exact intent atomically. A BINARY prefix range handles legal percent/underscore
characters without LIKE expansion and leaves adjacent siblings untouched.
Rollback/cancellation and idempotent completion are tested. Normal scanning
publishes RW conflict trees and descendant tombstones; RO copies stay local.
Receiving more remote work, ancestor/type ordering and manifest barriers still
require the unfinished pull coordinator.

Metadata preparation preserves creation time, effective access and DACL
protection. Windows normalizes directory-only ACL inheritance flags when
setting a file DACL; the retained old directory keeps its original ACL.
Original read-only/hidden attributes are restored, including recovery after
the move and before attribute restoration. The winner receives its signed
attributes. Diagnostics continue using bounded stages/session/native codes
without path/content/hash/envelope fields.
