# P1.2.4b2b2c: local bounded historical metadata cleanup

Migration 18 gives archive content manifests a durable retiring state. After a
fresh fully covered authenticated snapshot under both maintenance gates,
cleanup marks explicitly released manifests and drains at most 1,000 changed
or deleted metadata rows per FULL transaction. Bounded worklists avoid rescanning
all live manifests for each small source deletion. Partial drains remain hidden
from active/pending readers, appending and activation. Later recapture cannot
cascade-delete their outstanding chunks. Restart resumes the committed drain.

Cleanup preserves archive rows and attached provenance. Detached released
sources disappear only after content, holds, coverage and completed witness
links are drained. Pending or foreign recovery links remain protected. Completed
witnesses expire only when unlinked, no release depends on them, and they exceed
ArchiveDays. Absence never authorizes release. Byte-reference hashes, needed
requests, ownership/orphan clocks and native deletion journals remain unchanged.
Results/debug counts expose mutations and remaining work, with a retry hint for
another bounded batch. This metadata operation never removes filesystem data.

History reuse now durably repopulates the exact authenticated source chunks
from its held verified native copy before renewing retention. This also handles
legacy/missing cache bytes and prevents a renewed hold from depending on a
retiring partial manifest. SQLite failure retains the old copy/current data,
source release state and recoverable application intent; ordinary recovery
retries capture/accounting without forging another signed version.

Eleven new Storage cases cover a 1,001-chunk bounded drain/reopen, stable byte
references, attached/unreleased source preservation, reactivation/recapture
while an older drain finishes, pending/foreign metadata, witness audit age,
actual SQLite rollback, stale/root/pending/cancelled requests and v17-to-v18
backup/migration with active content and stable source identity preserved.
Four native cases exercise the real sweep, restart after FULL metadata commit,
needed/current byte preservation, missing signed-cache recapture before renewal,
actual recapture failure/recovery and diagnostic privacy. The first focused
Storage run covered ten cases; the final canonical run includes the migration
case. Focused native verification covers all four additions.

The final local `build/Verify.ps1 -SkipFuzz` passes all 830 tests (126 Core,
15 Crypto, 5 Protocol, 522 Engine, 162 Storage), native probes, diagnostics,
watcher recovery, QUIC diagnostics and publishing in 108.0999296 seconds,
exit 0. Separate CI fuzz is explicitly skipped locally. Scoped compiler/analyzer
diagnostics for both production and both changed test projects are clean,
without load warnings or truncation. The preceding full run passed 829 cases;
the final run adds the active-content v17 upgrade check.
