# Scheduled recovery and incremental scan hardening

PR #33's first head passes all five jobs, but review identifies five real gaps.
They are repaired together before merge:

1. Persist scheduled-deletion authority in bounded local intent formats 5 (file/
   type transition) and 6 (directory). Prepared recovery reacquires the reference
   gate and checks the sender's current advertised range through native mutation
   and commit. Incomplete knowledge retains target/journal and reports a typed
   IndexRangeRecoveryPendingException; index receipt remains available. Staging
   abandonment requires no barrier. Legacy direct kinds 1/3 and restore/history
   formats retain their previous semantics. Range-read exceptions release leases.
2. Unrepresentable live Windows mtimes produce a per-item Blocked outcome before
   reserving an intent; independent work continues with durable retry metadata.
3. Filter local paths invalid on the wire before incremental needed recomputation,
   preserving Scanner's unsyncable native rows and valid independent pulls.
4. Include native-cache-only updates in ChangedPaths so creation-time-only changes
   invalidate the target fingerprint and old retry delay without publishing a new
   signed local version.
5. Mark needed repair pending before scanning. Clear it only after recomputation
   succeeds. Cancellation or failure after committed local/cache/needed batches
   forces full needed rebuilding on the next pass; fresh coordinators already
   rebuild at startup. An unchanged second walk cannot hide missing needed work.

Fifteen added native cases exercise prepared/archived file and three directory
recovery boundaries after a higher target, exclusion through recovery commit,
unprepared abandonment, an actual range-query SQL failure with subsequent index
receipt, both file/directory timestamp boundary kinds, non-NFC input, native-cache
retry invalidation, and cancellation/SQLite failure after local rows commit while
needed is empty. The latter repair succeeds even when the next scan is unchanged.
The existing cache-only scan test now checks its changed-path result as well.

All 568 Engine cases pass. Canonical `build/Verify.ps1 -SkipFuzz` passes all 897
tests (126 Core, 15 Crypto, five Protocol, 568 Engine, 183 Storage), native probes,
diagnostic/watcher/QUIC checks and publication in 109.4136451 seconds, exit 0.
Separate CI fuzz is explicitly skipped locally. Scoped Engine/Engine.Tests
compiler/analyzer checks and the full build are clean. Logs/TRX:
