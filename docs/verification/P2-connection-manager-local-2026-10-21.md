# P2 connection manager local verification — 2026-10-21

`PeerSync.Net.Connections.ConnectionManager` now accepts already-authenticated candidate dialers, sorts them LAN, public, punch, then relay, starts attempts 250 ms apart, verifies each session's remote certificate-derived DeviceId, and keeps the first authenticated candidate. It cancels pending attempts after a winner and disposes any late sessions.

For simultaneous incoming and outgoing sessions, both peers apply the §8.3 preference: the lower DeviceId keeps the session it initiated. A stable SessionId tie-break handles duplicate sessions with the same direction. `MaintainConnectionAsync` retries after disconnect or failed attempts with exponential delays starting at one second and capped at five minutes. `ManagedPeerConnection.FromQuic` adapts the authenticated QUIC session lifecycle.

All 25 `PeerSync.Net.Tests` pass, including six new manager tests for source priority and fallback, first authenticated winner, both ends of duplicate resolution, wrong identity rejection, and backoff values. Candidate discovery and manager hosting were not yet wired when this evidence was first recorded; this is component-level evidence, not LAN deployment validation.
