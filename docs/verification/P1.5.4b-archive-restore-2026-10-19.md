# Archive restoration through local change — 2026-10-19

`ArchiveRestorer` composes the folder's `FileApplier`. Restore verifies the
indexed source hash/size under pinned root-relative guards, copies into owned
sibling staging and uses the approved recoverable archive/install protocol.
It preserves the current target, including unscanned edits, and retains the
source archive. Restore-as-copy takes an explicit destination and never
overwrites an occupied name, including a file created during copying/recovery.
New copy parents are created without overwriting existing entries or traversing
reparse points. Existing target DACL/protection and creation time are retained;
the restored bytes get the current local mtime and archived read-only/hidden
flags. Configured oversize/keep-both policy retains current data as a conflict.

Completion durably accounts for retained files, withholds stale local metadata
and removes the intent. The normal watcher/caller then scans: RW access
increments the local counter and signs a fresh local record exactly once;
RO access keeps the edit unpublished and ordinary overwrite policy still
applies. The operation never republishes an archived signature. A distinct
bounded local intent format (kind 2) contains unsigned local expectations;
existing signed remote intent kind 1 remains byte-compatible and authenticated.
One recovery entry point dispatches both before scanning. Tests reject local
intent bytes as a forged remote record through the real index receiver.

32 restore cases cover RW/RO semantics, preservation, explicit copy/refusal,
unscanned edits, seven prepared mutation boundaries, staging interruptions,
database reopening, role change and missing source after preparation,
corrupt/missing staging rollback, concurrent targets, source verification,
empty files, DACL/creation time, attributes, root replacement, reparse rejection,
malformed local journals, native error diagnostics and privacy. These are
injected interruption/reopening checks, not physical power-cut validation.
