# Directory application and nonrecursive deletion — 2026-10-19

`DirectoryApplier` applies verified directory versions under the shared folder
operation gate. Pinned no-reparse parent/leaf handles support exclusive creation,
metadata/case changes and native empty-directory deletion. Directory snapshots
report logical length zero without asking the file-size API to read a directory.
File/directory type transitions are reported as deferred, preserving the file;
they remain a separate parent/conflict integration requirement.

Signed, bounded directory intents (kind 3) bind the root, expected local sequence,
original directory identity, desired signed record and logical vector. No
metadata/deletion mutation occurs before FULL-durable preparation. The shared
file/restore recovery entry point dispatches directory intents before scanning.
Staging interruption leaves empty creations for normal scanning. Prepared
recovery completes matching objects, commits already-missing deletions, and
preserves changed identities/types for rescan. Completion atomically commits
local/sequence/needed state and removes the intent. Directory guards remain
held through metadata completion; deletion handles close before confirming
absence. Delete-sharing readers retain pending intent until recovery can prove
the native name disappeared. No recursive tree deletion is used.

After receiving the advertised sender index range, apply the individual signed
child tombstones through the file applier before the parent. A nonempty parent
is physically retained, logically tombstoned and requests a normal scan. RW
scanning then publishes its survival and unknown children as local descendants;
RO scanning keeps local changes unpublished. A child created immediately before
native deletion survives the kernel's nonempty check. The caller must not use
a partially received index to resurrect a parent prematurely. Physical pull
ordering and the manifest barrier remain part of the unfinished puller.
