# P1.6.2a reproducible real-engine simulations (local)

The CsCheck 4.9.1 harness uses three to seven actual temporary NTFS roots,
SQLite indexes, scanners, signed index reception, immutable chunks and guarded
recoverable application through IPeerTransport. Generated cases edit, rename
and delete flat paths while some directional links are partitioned, delayed or
lose deliveries. After healing it waits for matching byte-hash trees, stable
publication high-water marks, empty needed sets and no application intents.
The independent SHA-256 preservation oracle requires every published payload
in a valid current/conflict file or indexed archive; private cache bytes alone
do not count. A native negative-control test proves this distinction, then
accepts the scanner's reconstructed archive after local deletion.

The first batch found a checker defect, not divergent user bytes: seed
1146310622 left a parked hidden `.!psp` temporary on one node. The first checker
incorrectly compared that internal file. The oracle now uses the same public
path validity rules as the engine, reports staging files separately and never
counts staging bytes as preserved user versions. The seed is a checked-in
regression test. Internal cleanup is still an open P1 task, and no filename
match authorizes deletion.

The corrected 100-case batch passed 100 distinct generated seeds, covering
three to seven nodes, 1,467 proposed operations and 980 published payloads.
Every case converged in two healing rounds and passed preservation. In total
36 staging files remained across the cases; these are not a cleanup pass.
The generated sampling took 74.5197815 seconds; the complete two-test process,
including the saved regression, exited 0 in 76.835 seconds. Evidence:
`artifacts/simulation/{cases.jsonl,summary.json}` and
`artifacts/tests/simulation-generated/`.

`build/Run-Simulation.ps1` defaults to 1,000 generated cases when explicitly run,
supports a smaller requested case count, restores caller environment, uses a
fresh per-run evidence directory and verifies the exact completed count. The
canonical runner executes eight generated cases plus the fixed regression and
loss-oracle test. CI uploads summaries, traces and zipped synthetic fixtures on
failure. A failed case can be replayed with `PEERSYNC_SIMULATION_CASE`; the
CsCheck seed is also reported. Sampling/replay semantics were checked against
the installed XML documentation and [upstream documentation](https://github.com/AnthonyLloyd/CsCheck).

Final canonical `build/Verify.ps1 -SkipFuzz` passed 958 test methods/cases
(129 Core, 15 Crypto, seven Protocol, nine Net, 608 Engine, 187 Storage and three
Simulation), native/probe/diagnostic/watcher/QUIC and publication checks in
114.4448456 seconds, exit 0. The property method executes eight generated
scenarios, not eight separately counted xUnit methods. Scoped Simulation
compiler/analyzer diagnostics are clean with no truncation/load warnings.
Evidence: `artifacts/p1-simulation-{build,runner,verification}.log`,
`artifacts/simulation/20261019T135516-8a9db6bdba894b36a8ed91a365f338a5/`.

This is local initial flat-path coverage, not proof of arbitrary hierarchy,
case conflicts, crashes, 100,000 files, 1,000 CI cases or five consecutive CI
days. P1.6.2 and Gate P1 remain unchecked. No new CI matrix job or rerun was
added: the eight-case smoke shares the required x64 job. Separate boundary
fuzz was skipped locally and remains a required unchanged CI job.
