# P1.3.1 SQLite plumbing — 2026-10-19

Microsoft.Data.Sqlite 10.0.13 is centrally pinned with locked transitive/native
dependencies. Each normalized path has one writer owner in the process, with
a bounded 1,024-operation channel and one worker. Each write owns a transaction;
exceptions and observed cancellation roll back before the next write. Dispose
drains accepted work, releases the owner and clears only that database's pools.
Callers dispose their independent read-only connections.

Connections use private caches, pooling, WAL, NORMAL synchronous mode, foreign
keys, a 5,000 ms SQLite busy timeout and memory temp storage. The connection
default command timeout remains 30 seconds as in the plan. Migrations are a
complete ascending sequence. Before each migration, SQLite's online backup
copies committed state including WAL data to a new side-by-side backup. SQL
and user_version commit together; failure preserves the prior schema/data.
Future and invalid schema versions are rejected. This is an in-process owner
guard for the single service writer; it is not an interprocess lock or a claim
to resolve alternate paths through filesystem aliases.

Local validation: 10 Storage cases pass, zero skipped, covering required
pragmas, actual read-only enforcement, 200 concurrent serialized writes, a WAL
reader during an uncommitted write, exception/cancellation rollback and recovery,
queued cancellation, online backup with a committed WAL kept open, failed
migration atomicity, future schemas, normalized-path ownership, graceful drain,
and repeated disposal across reopening. Scoped Storage analyzers are clean,
with no load warnings or truncation. The canonical local runner passed all
145 cases, native probes, watcher recovery, diagnostics and publishing in
167.57 seconds with fuzz explicitly skipped. Folder/central schemas and
