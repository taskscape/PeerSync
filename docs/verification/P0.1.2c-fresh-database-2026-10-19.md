# Atomic fresh database initialization

PR #32's first CI head passes every test but exceeds the 15-minute job limit
during x64 artifact upload and Server 2025 cleanup. Both job annotations name
the timeout explicitly. This is not evidence of a failing test or another
billing admission failure. The full required matrix and timeout stay intact.

Previously, opening a fresh folder database created 18 online backups and 18
schema commits. Db now reserves the new path using CreateNew, then checks
version zero and an empty schema under an immediate SQLite writer transaction.
Only that path initializes every migration in one transaction. The check also
guards against another process populating the file after reservation. Existing
files, including empty or populated version-zero files, retain the ordinary
backup-before-each-migration path. Exceptions and cancellation checks unwind
the fresh transaction before startup can expose the database. A failed initial
schema leaves version zero and no partial tables; its next open takes the
existing-file backed-up path.

Four added regression cases exercise successful atomic initialization, rollback
of a failure in the second migration and reopening, and both empty/populated
existing version-zero files with preserved backup contents. Existing committed
WAL backup, failed-upgrade rollback, future-version rejection, cancellation,
ownership and durable-write tests remain. All 16 focused Db tests pass. Scoped
Storage and Storage.Tests compiler/analyzer diagnostics report no warnings or
errors, no truncation and no workspace load warnings.

An isolated local comparison opens 30 actual folder databases with all 18
migrations. Fresh initialization takes 0.2899698 seconds and creates zero
backups. Pre-created empty files take 1.2664363 seconds and create 540 backups.
The comparison measures initialization only, not hosted total runtime. The
probe and output are retained in `artifacts/db-init-probe/` and
`artifacts/p1-fresh-db-measurement.log`; no benchmark data was deleted.

The canonical `build/Verify.ps1 -SkipFuzz` runner passes all 834 tests (126 Core,
15 Crypto, five Protocol, 522 Engine, 166 Storage), native P0 and diagnostic
checks, watcher, published QUIC validation and x64 publication in 108.9796376
seconds, exit 0. Fuzz is explicitly skipped locally and remains the separate
required 600-second CI job. Full log: `artifacts/p1-fresh-db-verification.log`.
The total local time is essentially unchanged from the preceding run; the
initialization comparison does not establish a hosted runtime saving.
Hosted results remain pending. No task is ticked on this local evidence alone.
