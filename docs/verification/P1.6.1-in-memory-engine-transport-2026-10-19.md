# P1.6.1 transport-backed folder engine (local)

`IPeerTransport` now carries Hello, bounded index pages/range targets and block
requests. `InMemoryNetwork` grants source identity through registered endpoint
handles and creates an independent handler for each connection. It freezes
Hello/block buffers and device identities, injects directional latency, loss and
partitions on both delivery legs, and limits a connection to 64 outstanding
requests. Waiting index calls do not serialize block responses. Disconnect
cancels/drains operations before handler disposal, including when cancellation
callbacks throw. Request diagnostics contain opaque sessions, W3C traces,
operation names, elapsed time and managed errors, without payloads or device IDs.

`TransportFolder` owns a pull coordinator and routes all connected remote chunk
fetches through the interface. Connection-scoped Hello checks bind to transport
identity and the existing clock facade. Outgoing indexes/blocks and incoming
index commits recheck clocks. `PeerFolderConnection` announces targets, resumes
the durable received cursor, processes bounded page passes, rejects nonprogress,
and cancels/drains its queued index operations on disconnect. The host still
owns folder keys/indexes and must stop folder work and drain inbound transports
before folder disposal.

Nine Net tests cover identity/handler isolation, frozen handoffs, both delivery
directions, cancellation and live partition changes, independent requests,
capacity, orderly and exceptional disposal, malformed bounds/responses and
private diagnostics. Eleven Engine cases use real temporary NTFS folders,
signed indexes, guarded application and immutable published chunks: three-node
forwarding, overwritten-version preservation, partitions/healing, durable retry,
reconnect, skew/clock jumps, forged Hello identity, 1,001-record pagination,
queued admission cancellation and duplicate connection cleanup.

Canonical `build/Verify.ps1 -SkipFuzz` passed all 955 cases (129 Core, 15 Crypto,
seven Protocol, nine Net, 608 Engine, 187 Storage), native/probe/diagnostic,
watcher/QUIC and publication checks in 104.9092353 seconds, exit 0. Net is now
included in the canonical runner; no skeleton project is counted. Separate CI
boundary fuzz was explicitly skipped locally. Scoped Net/Net.Tests/Engine/
Engine.Tests/Storage compiler and analyzer checks are clean, without truncation
or workspace-load warnings. Evidence: `artifacts/p1-transport-*.log`,
`artifacts/p1-fabric-*.log`, `artifacts/p1-connected-engine-*.log`,
`artifacts/tests/in-memory/`, `artifacts/tests/transport-folder/`.

Roslyn impact checks resolved PeerIndexSession/Puller with one changed type
contract each, no implementations/overrides/callers, two production references
each, zero/six bounded test references and four dependent projects, without
truncation or load warnings. A broader FolderIndex query was truncated; the new
scalar reader is additive and the focused ReadIndexHighWater query identifies
its actual caller rather than inferring changes to all existing callers.

This work remains local, with no new Actions run submitted. P1.6.1a/b and clock
admission stay unchecked pending merge and green CI. The fabric is a trusted
simulation context; it does not implement P2 TLS/folder authentication or wire
framing. The rendered clock warning remains mandatory. These scenario tests
are not the random multi-node simulation, five-day CI evidence, or 100,000-file
zero-loss run required by Gate P1. The production service remains unavailable.
