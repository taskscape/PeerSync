# P1.1.5 ignore matcher — 2026-10-19

Implemented the specified gitignore-style subset: `*`, `?`, whole-component
`**`, comments, root/multi-component anchoring, directory-only rules and
case-insensitive matching. Windows separators in rules are accepted. Wildcards
match Unicode scalar values, including supplementary letters and emoji.
Negations follow last-match order; excluded ancestors remain excluded until
explicitly re-included. Initial `#` and `!` can be escaped. Bracket character
classes are outside the specified subset. Rules are immutable and use glob
matching plus dynamic programming, with no regex backtracking or filesystem I/O.

Defaults match the design. Internal `.psp`, temporary suffixes and invalid
record paths remain excluded even through negation. Rule text is limited to
64 KiB, 1,024 effective rules including defaults and 4,096 characters per line.
Malformed Unicode and limits produce redacted configuration errors.

Local validation: 106 Core cases pass, zero skipped; scoped Core analyzers
are clean without workspace-load warnings or truncation. The new cases cover
the documented Resilio wildcard/path examples, anchoring, recursive and trailing
double stars, directory inheritance, comments, negation, defaults, parser
limits and adversarial star patterns. A CsCheck property runs 10,000 generated
tree examples. The fuzz target also mixes arbitrary rule text with known
positive/negative matches; full-duration evidence remains a separate CI check.

Primary references: [Resilio IgnoreList examples](https://help.resilio.com/hc/en-us/articles/205458165-Ignoring-files-in-Sync-Ignore-List),
[Git ignore semantics](https://git-scm.com/docs/gitignore).
PeerSync deliberately uses Windows case-insensitive matching; this report
does not claim compatibility with Resilio's existing-index behavior or Git's
complete pattern language. The task remains WIP pending merge and green CI.
