# P1.3.2 folder index — 2026-10-19

Migration 1 creates the plan's `local_files`, `remote_files`, `needed`, `chunks`,
`devices`, `archive` and `meta` tables and archive-time index. Typed, parameterized
repositories cover upsert/read/find/delete for every table; SQL identifiers are
fixed in code. Unicode path keys use upper-invariant casing. Records retain
exact body/signature bytes; remote original-case names remain in their bodies.

Each prepared-command batch commits at most 1,000 rows. Local sequence allocation,
file row, supplied chunk replacement and the metadata counter commit together.
Physical local metadata deletion clears chunk references; filesystem deletion
is represented by a signed tombstone. Index batches read their sequence high
water and records in one read snapshot, safely advancing over unpublished gaps.
Unsyncable local names can be retained without a signed record and never appear
in published index batches. Remote paths always pass strict path rules.

Focused Storage cases cover every table, Unicode/case keys, opaque envelope
and vector round trips, allocated sequences, chunk replacement/deletion,
1,000-row batch boundaries, rollback on sequence overflow, unsyncable local
metadata, hostile remote paths and concurrent cursor reads at batch sizes
1, 7 and 1,000. Existing Db concurrency/migration tests remain included.
Scoped Storage analyzers are clean with no load warnings or truncation.

The reference-PC benchmark indexed **1,000,000 rows** in 5.3461 seconds and
finished count/counter verification plus disposal/reopen in **5.3767 seconds**,
passing the 60-second target. It retained 1,000,000 rows and sequence 1,000,000;
the database is 326,504,448 bytes. This is synthetic metadata indexing with
opaque fixture envelopes, 1,000-row transactions and a warm local NVMe. It
excludes filesystem scanning, content hashing and real signatures. It is not
a Windows Server VM or Arm64 performance result.
