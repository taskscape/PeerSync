# History-aware retention accounting — local progress, 2026-10-19

The native regression reproduces premature expiry: a newly retained snapshot
reuses matching bytes from a 31-day-old private archive, then ordinary pruning
removes that archive immediately. Its authenticated marker has a fresh history
observation time, but pruning previously used only the older archive-row date.
Independent blocks still protected the content; block sweeping must not be
enabled with this policy mismatch.

Migration 13 adds root/native-file/source-bound history accounting. The engine's
protected completion commits the exact marker, optional archive/provenance,
retention link and intent removal in one FULL transaction. Existing verified
markers can establish accounting only after an exact-byte compare-and-swap.
Public copies receive accounted links without inventing private archive rows.
Changed generic marker writes invalidate their accounting; missing/foreign-root
links cause archive maintenance to wait before recovery, age or capacity deletion.
Legacy key-holder bootstrap remains required in the complete retention manager.

Private age selection and capacity ordering use the maximum of the original
archive date and linked history observation times. The original row timestamp,
file attributes and native metadata are unchanged. New holds cannot attach to a
source already reserved for policy deletion. History preserves another verified
copy instead, including when the original marker had been completed before the
policy reservation. Old copies remain independently recoverable/prunable.

New policy reservations also FULL-bind their witness ID to the stable provenance
source ID. A completed witness keeps that association when a later archive row
reuses identical numeric ID and metadata. Migration deliberately does not guess
associations for preexisting witnesses; the later release policy must handle
legacy protection explicitly.

Five native cases cover the exact premature-expiry regression, capacity order,
pending-reservation fallback, invalidated accounting and real SQLite failure/
retry. Nine Storage cases cover atomic completion, public/private links, rollback,
exact-byte legacy accounting, invalidation/deletion, stable policy binding and
ID reuse, frozen buffers, cancellation, root/source rejection and v12 migration.

`artifacts/tests/history-retention-repro/`; it fails with Removed=1 before the fix.
