# Persistent block reference snapshots — 2026-10-19

Migration 10 stages bounded current, needed and history references in SQLite.
FULL activation replaces the prior active epoch atomically only after complete
root-bound, authenticated enumeration. Cancellation, failed batches and failed
activation leave the prior active snapshot intact. Startup discards abandoned
staging without discarding active protection. Hash length disagreements fail
the batch; reference kinds merge without retaining all distinct hashes in RAM.

The production collector includes chunk hints for unsigned/withheld local rows,
authenticated local bodies, every candidate for each needed path and retained
history manifests. Archive coverage is tracked in SQLite using exact source,
destination, size and whole-file hash matching. Unmanifested archive rows are
reported. Capture recovery precedes collection, pending applications defer it,
and replaced roots or invalid signatures prevent activation.

Maintenance acquires the filesystem gate then the separate reference/index
gate. Index receive and needed recomputation acquire only the latter. The
initial single-gate experiment deadlocked the existing newer-index-during-
assembly regression; this ordering preserves index reception during downloads
while excluding it during reference enumeration. Queued inputs are frozen
before waiting, and cancellation releases both gates.

Seventeen native cases and fourteen Storage cases cover authenticated/unsigned
sources, needed candidates, missing retained history, tampering, roots, bounded
batches, durable activation rollback, restart, capture recovery, serialization,
cancellation, archive coverage and diagnostic privacy. The canonical
`build/Verify.ps1 -SkipFuzz` passes all 633 tests (126 Core, 15 Crypto, 5 Protocol,
402 Engine, 85 Storage), native probes, diagnostics, watcher recovery and probe
publishing in 101.2376894 seconds, exit 0. Local fuzz is explicitly skipped;
the separate required CI job remains enabled. Scoped Engine, Storage and
Benchmarks compiler/analyzer diagnostics contain no warnings or errors.

The real 100,000-file warm local SSD corpus passes initial capture/hash/sign/
index work in 20.1345391 seconds and its unchanged walk in 0.8878611 seconds,
with zero hashes/updates and unchanged sequence. Production reference refresh
over its 100,100 rows takes 10.999693 seconds, yields the expected 251 distinct
one-byte blocks in one batch, and passes all kind/length checks. This measures
many manifests sharing 251 blocks, not 100,000 unique large files. Benchmark
mode is `--references-existing <corpus> --files 100000`.

Evidence is `artifacts/p1-block-references-verification-final.log`,
`artifacts/verification-win-x64.json`, TRX under `artifacts/tests/`, and
`artifacts/p1-block-references-scan-100k.log`. Affected-symbol tool invocation
for the benchmark method was unavailable; bounded type inspection, local
call-site inspection and full solution compilation cover that change.
