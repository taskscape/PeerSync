# Native directory case-root recovery checkpoint

P1.5.3h4c remains WIP. Authenticated case roots can now be created and recovered
through real native handles. This creates only the destination root; descendant
materialization/member journals and complete subtree publication are not yet
implemented. The case source remains pending even for an empty graph. The
production scanner snapshot gate stays inactive, and all five connected subtree
preservation failures remain mandatory.

The new local kind-8 intent binds the physical root, exact authenticated
directory envelope/source ID, collision slot, sibling GUID temporary directory
and native ID, and preparation state. Bounds, canonical flags, source identity,
directory snapshot, destination/temporary relationship and intent binding are
validated during decoding. The existing kind-7 file intent is unchanged.

Preparation requires a complete non-retiring source graph. Metadata fetch can
fail over only to current advertisers of the exact original root envelope,
retaining the successful route within that assembly. New graph work shares a
1000-unit pass budget. A failed call may already have committed progress, so it
conservatively consumes its offered budget. Successful partial work stays due
immediately; unavailable/retiring graphs and installed roots awaiting members
use persistent backoff rather than spinning.

An exclusive owned temporary precedes FULL source/destination intent reservation.
Only empty staging is prepared with inherited metadata and source mtime. FULL
prepared state precedes held-handle no-overwrite rename; FULL case-ledger native
identity accounting and intent removal follow installation. Unknown occupants
and indexed names select another slot. Accounting failure after rename retains
the intent for recovery before scanning.

Recovery recognizes a prepared installed root by its persisted native ID and
preserves post-install user children/metadata. A valid empty prepared temporary
can finish installation. Changed/unprepared/colliding/unclassifiable work keeps
all objects, parks verified staging (protected when changed/nonempty), and
releases the intent for a safe retry. Replaced accounted roots are preserved
and another slot receives a fresh identity. No root-only step clears the
original namespace barrier or claims descendant byte readiness.

Debug stages correlate reservation, preparation, installation, accounting and
replay by intent ID. Accounting failures include exception type, HRESULT and
SQLite extended/native error number without SQL text, source paths, payloads
or keys. The SQL-trigger regression verifies error 1811 and zero dropped events.

## Validation

- All 82 focused capture/projection/native-root cases pass locally, 7.89 seconds,
  exit 0 on the final accounting instrumentation. Nineteen root cases cover
  five crash boundaries with database reopen, unknown file/directory occupants,
  edited prepared staging, post-install children, diagnostic redaction,
  accounting rollback/replay, recovery collision, retiring graph rejection,
  malformed journal guards, RW/RO source attributes/publication behavior,
  replaced root identity and bounded continuation/failure accounting.
- The budget regression advances one real graph unit at a time through three
  authenticated file members and creates no destination until the fourth pass
  completes the graph. A two-source fixture fails after committed progress,
  proves the second source did not consume additional graph work in that pass,
  and resumes the independent source on the next pass.
- The complete Engine checkpoint contains 866 cases: 861 pass, five fail,
  zero skipped, 28.17 seconds, exit 2. Its failures are exactly the four
  flat/nested arrival-order directory clash variants and the file-wins-directory
  clash. The final accounting-error event/assertions were subsequently covered
  by the focused 82-case run; this is not a full-suite success claim.
- Engine and Engine.Tests compiler/configured-analyzer checks are clean with
  no workspace load warnings or truncation. No Storage schema/API change was
  required. Existing FULL case-ledger and staging operations are reused under
  their native/reference/operation-gate contracts.
- No canonical acceptance, new GitHub CI run, feature PR or merge was attempted.
  Local testing cannot close the five remaining subtree regressions.

Static impact analysis preceded edits. FileApplier had one contract, zero
implementations/callers, all four production references returned, ten of 120
test references returned (truncated), and all seven dependent projects returned.
FolderIndex had one contract, zero implementations/callers, ten of 58 production
references and ten of 419 test references returned (both truncated), and all
nine dependent projects returned. The exact case reservation/accounting,
staging and recovery dispatch code was inspected; no ambiguous identity or
workspace load warning remained. Static analysis is separate from runtime proof.
