# Recoverable local supersession history — 2026-10-19

`SnapshotHistory` reconstructs the prior authenticated live-file version from
independent published blocks before the scanner replaces its committed row
with a content-changing edit, deletion or directory. It never opens/writes the
current user target. Metadata-only changes with identical bytes need no
duplicate content archive. Unsigned RO edits have no prior published snapshot
to invent. Prior forwarded versions on RO peers can be retained normally;
resulting local changes/copies remain unpublished.

The same folder settings choose ordinary mirrored archives or public conflict
copies for keep-both/oversize versions. Signed source mtime and read-only/hidden
attributes are applied to reconstructed copies. ACL/creation metadata inherit
the new destination; those fields were not captured in the old signed manifest,
so this does not claim to reconstruct an unavailable old DACL/creation time.
Already indexed archives for the exact original path/hash/size, and scanned
conflict-tree descendants with the same native identity/hash, can be reused
without changing their metadata or duplicating archive accounting. Keep-both
still requires a public copy. Unverified/hardlinked retained objects stay
untouched while another independent history copy is reconstructed.

Kind-4 local intents bind root identity, source device and exact authenticated
body/signature, expected source sequence, capture time/fate, owned staging ID,
collision slot and any reused retained location. Decoding is bounded and verifies
the source signature and path rules before filesystem work. Exclusive GUID
staging writes verified chunks, checks the independent whole-file hash, sets
mtime and flushes before FULL-durable preparation. No-overwrite installation
rewrites the durable collision slot as needed. Metadata-only classification can
distinguish a locked unknown collision without opening it for data/mutation;
the final owned object is still verified under a no-write/no-delete guard.

FULL-durable history completion atomically writes optional archive accounting,
an exact-source manifest/location marker, and removes the exact intent. The
current source row/sequence are unchanged. This marker prevents duplicate
archives if the later scan commit fails or the process reopens. It retains the
authenticated manifest for future reference-aware cleanup/recovery. Migration 6
adds the indexed `(original_path,file_hash,size)` archive lookup; backup and
EXPLAIN coverage confirm migration and index use.

The shared recovery entry point dispatches history intents before scanning.
The scanner also recovers its own kind-4 work under the shared folder gate,
while unrelated application intents still block scans. Recovery resumes owned
staging or completes installed copies; missing/replaced staging is rebuilt from
blocks without deleting unknown objects. Newer current user data is never
rolled back. Failed recovery withholds the source while retaining its sequence
and intent. Missing/corrupt historical bytes fail visibly, leaving current user
data intact. Root/reparse changes fail closed. Explicit corruption/cancellation
and native/SQLite error metadata are logged by intent ID, with counts-only
copy progress every five seconds, without names, hashes, keys or raw records.

Public histories request a follow-up scan so ordinary RW publication discovers
them even with the watcher disabled and a long periodic interval. Scheduler
content-verification failures use bounded retry and release the global scan
permit for healthy folders. The source pathname is checked again after history
I/O and before the ordinary scan batch commits.

35 native history cases cover edits/deletes/type changes; all nine durable/scan
boundaries with database reopening; newer user data surviving recovery;
keep-both/oversize and RO policy; metadata-only/unsigned local no-ops; missing or
corrupt historical blocks and source withholding/retry; ordinary and locked
collisions; both cancellation boundaries; source mtime/read-only/hidden flags;
reparse parents/root changes; safe diagnostics; malformed/signature-invalid
intents; missing/replaced prepared staging; empty snapshots; public-fate policy;
existing archive reuse/recovery without metadata changes; and preservation of a
hardlinked unverified archive. Two scheduler cases exercise follow-up publication
and healthy-folder progress during bad-cache backoff. Four Storage cases cover
both accounting forms/idempotence, stale sequence/marker rejection, source
withholding without sequence changes, and a real SQLite-trigger failure that
rolls back archive/marker completion while preserving the intent.
