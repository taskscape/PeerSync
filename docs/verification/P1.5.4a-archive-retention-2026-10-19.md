# Archive placement and retention — 2026-10-19

`ArchiveManager` implements indexed cleanup and its daily background host.
The file applier now shares `ArchiveNames` for mirrored UTC timestamp names,
bounded Unicode components and no-overwrite collision numbering. Existing
file-application regressions cover actual archive placement and collisions.

Maintenance shares the folder operation gate, checks the persisted root
identity, and waits for pending file recovery. It resolves capacity from the
held root's volume GUID and the native actual allocation units, independent
of user quotas. Age expiration precedes cap eviction in oldest-first order.
Missing entries are reconciled before budget selection. An unavailable oldest
entry blocks cap-only eviction of newer versions, while independently expired
entries can still be pruned. Changed, unverified, locked, reparse and unindexed
data are preserved; unresolved entries can leave the cap unmet until retry.

Eligible files are opened through pinned no-reparse ancestors with a mutation
guard, size/hash checked, and marked for native deletion. Read-only attributes
are handled through the guard. Metadata is removed only after the path is
absent. A delete-sharing reader can keep deletion pending; its metadata remains
until a later pass confirms absence. A concurrent replacement at the archive
name is preserved. Interruption after data deletion leaves a missing row that
the next pass reconciles. No unknown directory sweep or recursive data cleanup
is performed. Duplicate archive paths fail closed before data eviction.

A successful timestamp survives host restart, preserving the remaining daily
interval. Deferrals retry at 10–600 seconds. Transient SQLite busy/locked/I/O/
full/open errors retry with extended result codes in diagnostics; corruption
and not-a-database remain fatal. The tests inject SQLite exceptions through
the existing clock seam, not an actual full disk. Diagnostic output is best
effort and contains stages, opaque sessions, counts, retry delays and numeric
errors, without names, hashes, contents or keys.
