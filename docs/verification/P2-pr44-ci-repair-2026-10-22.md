The [third PR run](https://github.com/taskscape/PeerSync/actions/runs/39767094436)
passed ARM64, Server 2022 and Server 2025, and its x64 Net suite (48/48), including
`ProofIsDirectionalAndBoundToBothCertificatesNoncesAndFolder` and
`DifferentCertificateDeviceIdFailsThePinBeforeFolderAdmission`. Its x64
Service suite passed 31/34. The same three installed-host cases now report
`QuicException: Stream aborted by peer (1)` during `PeerNetworkRuntime`
disposal; the final Windows sharing/lock violation is only a diagnostic.
The first causal stack reaches `PeerHandshake.ExchangeInitialHelloAsync` from
the QUIC listener accept loop. A peer abort during Hello faulted that
long-lived loop, which surfaced when the host was disposed. The Service
runtime now rejects and logs recoverable per-connection handshake failures
inside the accept loop, while unexpected listener failures still fault it.
Cancellation-time QUIC aborts are treated as normal shutdown. A new native
regression aborts the control stream, observes rejection without listener
failure, then completes authenticated clock recovery on the same host. The
network runtime now drains sessions even if its accept task faulted, and the
host closes indexes/state before rethrowing a network-disposal failure; this
prevents a secondary fixture lock from hiding the original exception. The
focused test and all 34 local Service tests pass after the change. The Server
2025 artifact proves its native and complete Engine scope ended successfully
in 760.850 seconds under the revised 840-second verifier budget.
