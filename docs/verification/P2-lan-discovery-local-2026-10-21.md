# P2 LAN discovery: local component verification — 2026-10-21

`PeerSync.Net.Discovery.LanDiscoveryPacket` encodes a bounded versioned datagram containing a DeviceId, listener port, UTC-hour epoch and up to 64 truncated HMAC-SHA256 folder tags. The tag input binds the folder identifier, hour and DeviceId. Receivers reject malformed or stale packets, ignore their own identity and accept a peer only when at least one local folder tag matches in constant time. Tags rotate hourly; the current and adjacent hour are accepted for clock and boundary tolerance.

`LanDiscovery` opens UDP listeners on port 47820, joins `239.255.80.83` and `[ff12::5053]` on available multicast interfaces, emits to each active interface with TTL/hop-limit 1, and sends IPv4 subnet broadcasts. Address-change notifications add memberships for newly available interfaces. It emits a matched peer endpoint for the TCP dial layer and uses the safe diagnostic journal for startup, discovery, send, receive and callback outcomes.

`PredefinedHosts` validates configured `host:port` values, resolves DNS to distinct IPv4/IPv6 endpoints on startup and every 60 seconds, and passes each endpoint to an injected dial callback. Invalid entries and resolution/dial errors are recorded without logging hostnames or exception messages.

The focused `PeerSync.Net.Tests` suite passes 37 tests with zero failures or skips. New packet tests cover matching, duplicate tags, adjacent-hour rotation, stale rejection, bounds and invalid fields. Resolver tests cover DNS address expansion, endpoint deduplication, IPv6 literals, invalid endpoint rejection and the refresh interval. Block server error mapping tests verify stable protocol errors. The canonical local `./build/Verify.ps1` run passed all 1,663 tests and 14 simulation cases in 677.8646527 seconds; native probes and Windows publishing passed, and five-target fuzzing ran 600.0004276 seconds across 190,095 seeds with zero crashes. Its metadata correctly leaves `gateP1Passed=false`.

## Live multicast follow-up — 2026-10-22

`LiveMulticastDiscoversBothPeersOnAnActiveNonLoopbackInterfaceWithinFiveSeconds` starts two independent `LanDiscovery` instances with separate device identities and a shared folder key. Both instances receive the other's authenticated advertisement through active non-loopback interfaces, report the expected listener ports, and complete mutual discovery in 1.071 seconds. The focused test passed on Windows 10 Pro build 26300. A temporary inbound UDP 47820 rule scoped to `LocalSubnet` and the `Any` profile was created for the test and removed in its `finally` cleanup; inspection afterward confirmed the rule was absent. This adds live same-host socket and multicast evidence, but does not prove that two different PCs can exchange announcements. The complete Net suite also passed 39/39 with the live test included.
