# Four-node directory gossip reference baseline

P1.5.3h4b3 is WIP. Two connected baselines use four nodes, with RW/RW and RW/RO
receiver variants. Receivers first preserve the source subtree independently,
then every ordered pair participates in 16 gossip cycles, using bounded
`maxPages: 1` synchronization and injected UTC work deadlines. All transports
close before node/index teardown.

Both variants pass the assertions for every node's original/winner payloads,
one portable stable case-copy name, empty pending case/needed queues and no
pending directory publication. They then fail required reference coverage after
four bounded refresh attempts per node. Every node reports
WaitingForDirectorySnapshots=true and AllKnownSourcesCovered=false.
HasDirectoryCaptures=false rules out an abandoned capture hold. Diagnostics
show incomplete current directory graphs; later current graphs remain unvisited
after the first missing metadata stops activation. No sweeping is authorized.

The baseline intentionally retains these failures. Native data convergence and
drained queues are insufficient evidence of complete metadata availability.
Ordinary protected directory metadata needs transport-backed fetching and
logical apply needs snapshot reconciliation even without a native watcher event.
Follow the metadata-fetch proposal before changing these assertions or enabling
the ordinary production path.
