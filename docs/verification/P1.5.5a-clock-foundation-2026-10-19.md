# UTC Hello and clock decision foundation

Hello now carries UTC DateTime ticks. ClockGuard freezes that field and its local
monotonic receipt timestamp, estimates advancing peer UTC and compares current
local UTC. Exactly +/-600 seconds is allowed; larger offsets block its admission
check. Missing/default/invalid timestamps, backwards elapsed time and estimated
UTC overflow fail closed. Disconnect resets admission and a fresh sample can
restore it. Shared Core status exposes offset ticks and a display reason without
bringing engine/storage dependencies into a control client. Transition logs carry
session and numeric skew seconds without names, device IDs, nonce or key data.

All 18 clock cases and seven Protocol cases (two added Hello wire cases) pass.
They cover both signs/exact boundary, malformed values, frozen input, long elapsed
time, local clock jumps, reset, extreme arithmetic, presentation and privacy or
unavailable diagnostics. Canonical `build/Verify.ps1 -SkipFuzz` passes all 902
tests (126 Core, 15 Crypto, seven Protocol, 571 Engine, 183 Storage), native
probes, diagnostic/watcher/QUIC checks and publication in 108.9160632 seconds,
exit 0. Separate CI fuzz is explicitly skipped locally. Scoped Core/Protocol/
Engine/Engine.Tests compiler/analyzer checks are clean with no truncation or
load warnings. Evidence: `artifacts/p1-clock-*.log`, `artifacts/tests/clock-*/`.

This foundation remains local. Actual authenticated incoming/outgoing index
admission and the rendered control UI remain P1.5.5b/c; the parent and Gate P1
are open. The standalone RequireIndexExchangeAllowed check does not itself
enforce policy on the current raw pull APIs. Full P2 framing/authentication is
also separate.
