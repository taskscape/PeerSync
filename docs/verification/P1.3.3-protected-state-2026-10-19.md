# P1.3.3 protected central state — 2026-10-19

The machine state schema includes folders (identity, normalized unique root,
access level, protected key, settings JSON and pause state), devices, pending
approvals and append-only audit reads. Folder removal affects metadata only;
foreign keys remove pending approvals while audit history remains.

Folder writes accept `FolderKeys` and protect internally. The shared Crypto
protector uses Windows machine-scope DPAPI with the plan's unchanged fixed
entropy `PeerSync folder key v1`. Its versioned binary plaintext frame binds
role, FolderId and key material. Loading validates frame/role/context and the
re-derived identity. Temporary plaintext is cleared. Protected objects redact
diagnostics and expose only explicit ciphertext/identity exports; folder
listings contain no blob or keys. Machine-scope DPAPI does not isolate users
who obtain the blob: service/state ACLs remain mandatory in P2.

Successful key reads and registration/settings/removal changes are audited in
the same transaction. A key is returned only after its audit commits; a failure
or observed cancellation disposes the unreturned key. Caller authorization is
the service's responsibility, not an assertion made by this persistence layer.
Audit actors are validated SIDs and no key/body data is stored in audit rows.

Shared folder settings preserve the plan's defaults, reject unknown/duplicate
JSON properties and validate bounded ranges and host:port lists without
credentials or paths. Device settings, atomic settings-file recovery, service
ACL setup and sensitive-RPC authorization remain P2/P3 work.

Focused local tests cover all DPAPI roles, tampering, wrong folder/role, valid
DPAPI frames with invalid versions/material, redaction and disposal; settings
defaults/round trips/validation; state persistence, actual ciphertext in DB/WAL,
device and pending approval data, pause/settings updates, metadata-only removal,
case-insensitive root uniqueness, corrupt blobs and fail-closed audit errors.
The canonical local runner passed 174 cases, native probes, watcher recovery,
diagnostics and publishing in 97.89 seconds with fuzz explicitly skipped.
The additional cancellation-at-audit regression passed separately (24 Storage
cases now pass). Scoped Core/Crypto/Storage analyzers are clean without load
warnings or truncation. Storage and dependencies cross-published for Arm64;
SQLite, libsodium and BLAKE3 native payloads all have PE machine `0xAA64`.
