# P1.1.3–P1.1.4 signed records and path rules — 2026-10-19

Core owns copied body/signature bytes and can rewrite only the local sequence.
Protocol owns the generated Protobuf schema and signing factory, avoiding a
Core/Crypto dependency cycle. New records sort version-vector entries before
one serialization. Signing binds the exact bytes to `psp1 record` and FolderId.
Opening verifies before parsing, then checks paths and canonical vector entries.
P2 message validation will add the complete field/request limits.

The path guard rejects traversal, empty components, rooted/UNC/device paths,
drive-relative names, alternate streams, Windows reserved names (including
superscript COM/LPT digits), control characters, trailing spaces/dots, root
`.psp`, temporary suffixes, malformed UTF-16 and non-NFC input. Components are
limited to 255 UTF-16 code units and record paths to 4096. Valid Unicode is
preserved. Local mapping validates first, requires an absolute root and checks
its separator boundary. This is lexical containment; filesystem layers must
also reject reparse traversal.
