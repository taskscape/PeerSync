# P1.5.5c2a verified local control client (local checkpoint)

The shared client fixes production discovery to service `PeerSync` and pipe
`PeerSync.Control`. SCM handles request configuration/status read rights only.
The resolver requires Running/nonzero PID, reads the configured account using
a bounded native buffer and resolves well-known accounts without localized
names. Native strings must terminate within their allocation. Changed/stopped
or inaccessible configuration fails closed.

The 8 KiB bound and configuration semantics follow
[QueryServiceConfigW](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryserviceconfigw);
the account returned after a configuration change can describe the next start,
so identity mismatch requires a fresh lookup/restart rather than relaxed trust.
PID/state come from
[QueryServiceStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryservicestatusex).
The connector checks both owner SID and the
[kernel server PID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid)
on the connected instance before returning the stream to HTTP/2.

Connections use identification-level impersonation and a three-second
cancellable deadline. The channel disables proxy/redirect routing and caps
frames at 256 KiB; typed GetStatus and WatchEvents decode frozen snapshots.
Raw fixture descriptors remain internal and diagnostics redact their identity.

All 39 contract tests pass, including eleven new native identity/discovery
checks. Actual named-pipe bytes pass for the correct owner/PID; both mismatches
close before any HTTP/2/RPC bytes. Cancellation and missing-pipe deadlines,
read-only SCM lookup of RpcSs, missing-service native error, account aliases
and invalid/redacted endpoint values are covered. Builds have no warnings or
errors. The initial fixture inherited an administrator owner and awaited a
write-through send without a pending read; explicitly setting its owner and
starting the receiver first repaired the fixture while preserving strict checks.

Evidence: `artifacts/p1-control-client-{build,tests}.log` and
`artifacts/tests/control-client/`. No canonical run, real GetStatus server
integration, installed PeerSync service, UI or CI/main acceptance is claimed.
This local checkpoint is retained separately while PR #36 review fixes proceed.
