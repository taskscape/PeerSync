# Recoverable regular-file installation — 2026-10-19

Implements the user-approved two-move protocol from the source design. The
archival/install pair has a brief missing-target interval visible to external
applications. Final installation never overwrites a concurrent target. No
strict existing-target atomic replacement is claimed.

`FileApplier` shares the scanner's folder gate, validates the bound root, and
selects from verified signed records. It creates an exclusive GUID temporary
sibling, durably records ownership before assembly, verifies chunks and the
whole file, preserves replacement DACL/creation time and flushes the data.
Before destructive work it guards and rehashes the current target and persists
a bounded FULL-durable prepared intent with root, old/new identities, original
hash/metadata, signed desired record, logical vector and retention destination.
The exact guarded original moves without overwrite to archive/conflict storage;
the verified temporary then moves into the vacant target. Times precede
read-only/hidden attributes. Directory/file guards stay held until atomic
local/chunk/sequence/archive/needed completion removes the intent. Needed state
is recomputed against the latest transaction snapshot, including index updates
received during assembly.

Recovery runs without the network before scanning. Prepared data finishes the
install, missing/corrupt temporary data restores the retained original to a
vacant name, and staging ownership is parked for later byte-verified reuse.
An unknown concurrent target is preserved, verified archives are accounted for,
stale local state is withheld until rescan, and the intent is removed together.
Changed root/file identities, invalid/truncated recovery data, missing or
changed retained originals fail visibly with the intent intact. Staging names
alone never establish ownership. Windows may set Archive during rename; the
original attributes are restored after validating identity, size, mtime and hash.

29 native integration cases cover replacement, read-only files, deletion,
empty files, conflict copies and author naming, collision reservation, restored
mtime/case-only changes, cancellation, locked targets, redacted diagnostics, edits
during transfer, concurrent index updates, unknown targets in the gap and after
restart, changed installed bytes, corrupt/missing staging, substituted staging
identities, replaced roots and truncated recovery payloads. Boundary injection
and database reopening cover prepared, read-only-cleared, archive-moved,
archived, installed, case-renamed and pre-commit states. Archive directory and
file guards are checked during application and recovery. These are injected
interruption/reopening checks, not physical power-cut or multi-machine tests.

Validation: the canonical local runner passed 335 cases plus native probes,
diagnostics, watcher recovery and probe publishing in 92.43 s, exit 0, with fuzz
explicitly skipped. The final guard-lifetime change and new regression then
passed all 153 Engine cases, exit 0. There are 337 current cases (126 Core,
15 Crypto, 5 Protocol, 153 Engine and 38 Storage); the 335-case full execution
preceded the last two regressions. Build and scoped compiler/analyzer checks pass.
