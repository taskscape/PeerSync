# P1.5.3h1 case-clash regression baseline

Six new connected-engine cases exercise real NTFS roots, SQLite indexes,
signed records and verified chunks over the in-memory transport. The baseline
uses production code at submitted PR #35 head
`9f17d76f335e2b7940d060b5fcba2a4634e7cb0c`; this unfinished feature is not part
of that PR.

Four cases fail with the same causal assertion: two visible versions were
required but only one exists. Both remote arrival orders fail on an empty
receiver. Existing receivers fail whether ordinary content selection chooses
the local or remote version. Retaining bytes in private blocks or an archive
does not satisfy the design's visible `.case-conflict` behavior. This is a
missing preservation behavior, not evidence that all retained bytes are lost.
The two controls pass: an ordinary causal case rename, with and without a
content edit, creates no case-conflict copy.

The read path explains the gap. `NeededSet.Decide` groups records by invariant
path key, chooses a single version and merges every vector. `ToNeededRow` stores
only that selected work item. `FileApplier` stages the selected winner and
retains a local loser under the ordinary policy; it cannot materialize a
remote loser for an empty/local-winning receiver. After a merged version has
been forwarded, vector dominance can hide the initial case concurrency.

Before enabling mutations, admission needs durable competing source envelopes
and references captured atomically with accepted index updates, plus pending
case work that survives remote row replacement and vector merging. Original
signed paths remain unchanged; visible copies must use no-overwrite native
installation and ordinary RW scanner publication. First-name mapping,
deterministic suffix reconciliation across gossip, directory/nested mapping,
restart recovery, completed-source deduplication and reference retirement still
need a complete design. This child and its parent remain WIP.

The probe build uses `dotnet build tests/PeerSync.Engine.Tests -c Release
--artifacts-path C:/Projects/Sync/artifacts/case-baseline`. It leaves the ordinary
build outputs untouched while the submitted-head 1,000-case simulation runs.
The direct xUnit executable uses `-class '*CaseCoordinationTests'
-result-trx artifacts/case-baseline/case-baseline.trx`; its native options differ
from the `dotnet test` adapter. The six-case baseline exits 1 with four failed,
two passed and zero skipped in 0.736 seconds. Build/compiler/analyzer succeeds
after making its stateless fixture helper static (CA1822).

Evidence: `artifacts/p1-case-baseline-{build,tests}.log` and
`artifacts/case-baseline/case-baseline.trx`. These intentionally failing feature
regressions are local and must be repaired before submitting a feature PR.
