# P1.5.3/P1.5.4 safe mutation foundation — 2026-10-19

`SafeFileTree` pins a regular root and opens each directory component relative
to its held parent handle. No-reparse opens and explicit attribute checks reject
links before any write. Leases deny delete sharing on every ancestor, so those
directories cannot be renamed during an operation. The scanner's existing
shared-root behavior is unchanged; the mutation wrapper opts into pinning.

Exclusive `FILE_CREATE` produces sibling temporary files. A mutation guard
denies other writers/deleters, and `NtSetInformationFile` renames that exact
handle into a pinned destination without replacing an occupied name. Moving
into the private archive preserves the original file identity. These are
individual mutation primitives, not a complete multi-file transaction.
Remote directory paths and temporary components retain 4,096/255-character
bounds; private archive paths allow their fixed metadata prefix separately.

Four native Windows cases cover exclusive creation, flushed bytes, handle
identity across moves, occupied-name preservation, ancestor/root rename
exclusion and lease release, guarded writer/deleter exclusion, reparse-parent
rejection, path traversal and overlong components/paths before mutation.
The outside fixture remains unchanged. No replacement-through-link operation
is performed. Evidence: `artifacts/p1-safe-tree-tests.log`.

The local canonical runner passed 252 cases, native probes, diagnostics,
watcher recovery and probe publishing in 117.68 seconds, exit 0. Its log is
`artifacts/p1-safe-tree-verification.log`. Fuzz was explicitly skipped locally.
The final path-bound tightening then passed all 84 Engine cases, zero skipped;
scoped Engine and Engine.Tests compiler/analyzer checks are clean, with no
workspace load warnings or truncation. CI remains required.
