Migration 9 adds nullable native `change_filetime` cache metadata, with backup
before upgrade. Regular-file fast paths require the stored and enumerated
native change stamps to match. Legacy rows hash once. The streaming hasher
returns its verified stamp and scanning checks it against the enumerated
snapshot before publication. Applied files cache their final native snapshot.
Directory child timestamp changes remain excluded from directory versions.

When bytes and synchronized metadata match an existing signed version, preserve
its original partition/body/signature/vector. Cache-only updates compare local
sequence and file identity, change only the native stamp, and preserve chunks,
readiness and publication sequence. This also avoids version loops after safe
apply/restore rollback or unsynchronized creation-time changes. Read-only legacy
refresh never re-signs the forwarded version. Readiness backfill still advances
the sequence when a previously withheld version becomes publishable.

Renames alter native change metadata even without a data edit. Verify the entire
file under a no-write/no-delete read guard before reusing the former signed
partition. An edited rename falls back to normal hashing/capture and retains
the old snapshot. The existing `Renamed`/`Hashed` counters distinguish partition
reuse from FastCDC work; reuse now includes whole-file verification I/O.
