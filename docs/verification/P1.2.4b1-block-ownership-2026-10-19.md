# Durable block ownership and capture recovery — 2026-10-19

Migration 7 adds root/file-identity-bound block ownership with hash, length,
capture time and last use. Registration uses FULL transactions, clones submitted
arrays and rejects a missing/different root binding. Same-object registration
preserves the earliest capture and latest use; a new identity replaces those
times. Migration backup precedes the schema update. Legacy signed live files
are withheld until their content is independently verified and registered.
Directory, tombstone and unsigned local rows are unchanged by that reset.

Before writing staging data, capture flushes a fixed 156-byte proof binding the
root, proof/data file identities, expected hash/length, timestamp and GUID. Its
BLAKE3 checksum detects torn local metadata; it is not network authorization.
Proofs occupy a separate directory so a warm scan need not enumerate every
blob. Data is flushed and installed without overwrite. FULL ownership
registration precedes live-file readiness; proof cleanup follows registration.
Verified existing bytes matching caller-owned capture input can be adopted
without rewriting them. Unknown files are never adopted merely by their name.

Recovery precedes scanner history reconstruction and shared apply recovery.
It verifies proof framing/checksum/name/root/self identity and checks the data
identity, hash, size and independent regular-file state under native guards.
Complete owned staging can finish installation; installed data can be registered
after restart. Partial, changed, replaced, inaccessible, linked and reparse data
are preserved. Invalid proofs are deferred rather than blocking healthy scan
paths. Missing data permits cleanup of the verified proof only. A failed
database registration retains installed bytes and proof, and prevents publication.

Scanner, chunk assembler and incoming-file completion await ownership flush,
including captures completed before cancellation/failure. Read-only legacy
backfill preserves exact signed bodies, signatures, vectors and original chunk
partitions; it never captures an unsigned read-only edit. The ordinary sequence
advances when readiness returns so existing peers can discover the record.

Diagnostics distinguish catalog failure/commit, deferred proof cleanup and
capture recovery, with GUID correlation, counts, HResult, SQLite extended or
native error codes and retry metadata. They exclude paths, hashes, content and
exception/SQL text. Journal failures remain best effort.

adoption; installed/staged recovery; truncated/invalid/root/self/name/length
