# Peer-bound clock admission

Puller opens a peer-index facade only for an identity already authenticated by
its transport/folder context. That identity is frozen; Hello cannot override it.
Missing/skewed clock samples reject incoming records, target announcements and
outgoing index pages. Disconnect resets admission and a fresh Hello can restore
it. Outgoing pages freeze their record list, preserve exact signed bytes, enforce
count/order/cursor bounds, and are checked before reading and before handoff.

Incoming operations recheck clock policy after taking references and inside the
writer transaction at entry and before commit. Pure writer callbacks do not log
or reenter storage. ClockGuard's state lock no longer covers journal I/O. A clock
jump while the writer is busy, including an empty index batch, cannot commit
rows, needed descriptors, cursor or target metadata. Final admission denial rolls
all those transaction changes back. Existing raw engine/storage methods remain
trusted local primitives, with their old signatures preserved.

Eleven engine integration cases verify both offset signs, missing/reset/fresh
samples, frozen transport identity despite a different Hello ID, queued writer
and reference waits, exact outgoing signatures, post-read revocation, signature
validation, cancellation, and safe session/trace correlation. Four storage cases
exercise entry/final revocation for records/ranges and continued writer use.
Three Core cases exercise frozen pages, gaps, strict order and malformed bounds.
Clock and peer-index logs share an opaque session; needed operations share the
request trace. No device names/IDs, keys, record paths or payloads are emitted.

Canonical `build/Verify.ps1 -SkipFuzz` passes all 935 cases (129 Core, 15 Crypto,
seven Protocol, 597 Engine, 187 Storage), native/probe/diagnostic/watcher/QUIC and
publication checks in 110.2048556 seconds, exit 0. Separate CI fuzz is explicitly
skipped locally. Scoped Core/Storage/Engine/Engine.Tests compiler/analyzer checks
are clean with no truncation or workspace load warnings. Evidence:
`artifacts/p1-clock-admission-*.log`, `artifacts/p1-peer-clock-tests.log`,
`artifacts/p1-index-{admission,page}-tests.log`, `artifacts/tests/peer-clock-session/`.

This remains local. P1.5.5b stays open until production transport integration
uses this facade; P1.5.5c still requires the rendered control UI. Raw pull APIs
alone do not enforce authenticated clock policy, and P2 framing/authentication
is not implemented by this facade. Gate P1 remains open.
