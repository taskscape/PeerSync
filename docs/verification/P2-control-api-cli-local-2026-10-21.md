# P2 control API and CLI local verification

The first control API slice and the `psp` management commands pass the full local Windows verification run. No GitHub Actions result is claimed here.

The control pipe now supports `GetStatus`, `WatchEvents`, `ListFolders`, `AddFolder`, `JoinFolder`, `GetFolderKeys`, `ListPeers` and streamed `DumpIndex`. Each RPC identifies and authorizes the named-pipe caller. Folder registration audits the requesting Windows SID, opens the folder database and engine, verifies or creates the root `.psp/id` identity marker, starts a scan schedule, and makes the folder available to the live peer runtime. A marker containing a different folder ID prevents accidental joining with the wrong key. `GetFolderKeys` uses the state store's audit transaction and returns the requested share key only through that RPC. Debug events record operation names, counts, session IDs and safe error codes without writing keys or paths.

`psp status`, `psp add <path>`, `psp join <key> <path>`, `psp share <folder>`, `psp peers <folder>` and `psp dump-index <folder>` use the verified local control client. Add prints its newly generated share key by calling audited `GetFolderKeys`; `psp share` retrieves it again. Each supports `--json`; index rows stream so a large index does not need to be buffered in memory. `psp --help` was also run against the built executable and lists the commands.

The service pipe test adds a folder, reads and validates its audited share key, joins a second folder, lists both, reads peers, streams an indexed file, verifies that unauthorized callers are rejected for every RPC, and checks that the lifetime monitor remains active for components created after startup. The canonical command was `./build/Verify.ps1` on `win-x64`; it exited 0 with a zero-warning build in 791.504 seconds. Its test results were 1,667 unit tests and 14 simulation cases, with no failures or skips. The five-target fuzz run lasted 600.000 seconds, processed 171,669 seeds, and reported zero crashes. Native probes, QUIC diagnostics checks, and publishing probes passed. The canonical artifact reports `status=passed`, `phase=P1`, and `gateP1Passed=false`; those labels do not claim that Gate P2 passed.

The canonical runner also reports `runtimeChecks=true`, which covers its local probes.
