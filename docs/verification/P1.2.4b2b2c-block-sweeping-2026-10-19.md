# P1.2.4b2b2c: local verified owned block sweeping

Migration 16 distinguishes pre-cleanup ownership from new registrations and
adds root-bound legacy grace, durable orphan observations and exact deletion
intents. The first maintenance pass initializes the legacy window once for
ArchiveDays. A fresh activated reference or changed/reused registration resets
orphan observation. Normal orphan expiry follows ArchiveDays; capacity pressure
can retire unreferenced data after at least 24 hours of observed grace. Required
references and the legacy window remain protected even above the capacity cap.
Both pending intents and each native deletion pass are bounded to 1,000 objects.

`BlockRetention` bootstraps history and prunes archives, then holds the folder
gate followed by the reference gate through policy retirement, fresh reference
activation, observation, native verification and deletion/recovery. Pending
applications, uncovered archive sources and deferred capture proofs prevent
sweeping. Existing public reference/policy APIs retain their gate-taking
wrappers; internal maintenance paths borrow the held gates and pinned root.

Only an independent installed block matching its catalog root, native file ID,
length and whole hash can receive a FULL deletion reservation. The mutation
guard remains held before native deletion. Completion proves absence under
the pinned parent and FULL-removes only matching catalog ownership, orphan
state and the exact intent. Unprepared missing catalog paths reconcile metadata
without claiming a native policy deletion. Unknown names, changed bytes/IDs,
locked files, hardlinks and reparse paths remain untouched with visible codes.

Restart first refreshes references. Renewed references, replacement ownership
or changed grace cancel a still-present prepared deletion. If a block was
already deleted before a new reference arrived, completion withholds live local
readiness for ordinary rescan/backfill; it never advertises missing bytes as
ready. Needed requests remain present. Recovery precedes new deletion work.
Progress/debug records contain GUID sessions, counts, elapsed time, byte counts,
exception types/HResult and native/SQLite codes, without paths, hashes, content
or SQL exception text.

The final local `build/Verify.ps1 -SkipFuzz` passes all 767 tests (126 Core,
15 Crypto, 5 Protocol, 481 Engine, 140 Storage), native probes, diagnostics,
watcher recovery, QUIC diagnostics and publication in 111.0596706 seconds,
exit 0. Separate CI fuzz is explicitly skipped locally. Scoped compiler/analyzer
diagnostics for both production and both changed test projects are clean,
without load warnings or truncation. The initial full run passed 764 cases;
the final run also includes three additional native boundary/bound tests.

Eight new Storage cases cover age/cap/grace, fresh-reference resets,
registration/replacement, exact journal matching and actual SQLite rollback,
legacy v15 migration/reopen, 1,001-row observation and 1,000-intent bounds,
stale/foreign/pending/cancelled state, and missing metadata reconciliation.
Twenty-one native cases cover actual deletion, every interruption boundary,
new references before/after deletion, unknown/changed/locked/linked/reparse
objects, recapture, missing reconciliation, reservation/completion SQLite
failures and diagnostic privacy, pending/uncovered sources, gate cancellation,
incomplete capture deferral, held native mutation guards, and the production
1,001-object deletion bound across two passes.

The real 100,000-file corpus passes its unchanged scanner walk in 0.6787736 s
(zero hashes/updates, sequence preserved). Authenticated reference refresh
takes 8.0102123 s with the expected 251 distinct blocks and complete coverage.
This measures scanner/reference behavior, not five-node sync simulation.
