# P5 independent security review package

This is a handoff map for the P5.2 reviewer, not a completed independent
review. Review the [design threat table](../Resilio-style%20P2P%20Sync%20for%20Windows%20Implementation%20Plan.md#threats-and-mitigations)
against the implementation and use the [review record](security-review-record-template.md)
to capture the exact candidate revision, installed hosts, findings, severity,
reproduction, fix or accepted rationale before closing P5.2.

Independently test a mismatched certificate and protocol downgrade on both transports. |

A clock-controlled test confirms that the journal's timer removes an idle IP-bearing log after 24 hours without another write; see [local retention evidence](verification/P4-idle-log-retention-2026-10-23.md). The [fresh physical Add/Join](verification/P3-fresh-add-join-physical-2026-10-25.md) scanned 21 installed journals on both clients after exact bidirectional transfer, with zero matches for its capability, FolderId encodings or native paths. Later [Server 2025 upgrade](verification/P5-current-source-server2025-upgrade-2026-10-23.md), [Server 2022 client and Server 2025 central uninstall](verification/P3-server2022-uninstall-cycle-2026-10-23.md), [packaged field collection](verification/P4-field-deployment-collector-2026-10-23.md) and [three-PC crash-policy re-audit](verification/P5-crash-policy-audit-2026-10-23.md) verify those specific installed policies and cleanup paths. Independently inspect other component logs, the physical Rendezvous host's LocalDumps policy, OS telemetry and the [approved dump boundary](proposals/P5-crash-dump-boundary.md) before closing P5.2. |

For the crash-report boundary, run the packaged
[`Audit-CrashPolicy.ps1`](../installer/Audit-CrashPolicy.ps1) on each installed
client and Rendezvous host and retain its JSON with the review. The
[local audit evidence](verification/P5-crash-policy-audit-2026-10-23.md)
verifies the parser and local client state. The later installed-guest checks
above cover those specific hosts; neither local nor VM checks can inspect a
privileged full/live dump on every deployment host.

The 2026-10-26 `dotnet list PeerSync.slnx package --vulnerable
--include-transitive --format json --no-restore` audit queried NuGet.org
after locked restore. Its retained local report at
`artifacts/security/nuget-vulnerable-2026-10-26.json` has SHA-256
`040DA93A8D8F15CAAD1C2D5BED94E58FFB60D3EF14C5E262C5A2C8F31AA1A1CE`,
lists 35 projects and reports no vulnerable top-level or transitive package.
This is advisory coverage at audit time, not proof that the code or packages
are free of security defects. The independent reviewer should rerun it on the
release candidate and examine the pinned package set.
