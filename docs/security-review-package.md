# P5 independent security review package

This is a handoff map for the P5.2 reviewer, not a completed independent
review. Review the [design threat table](../Resilio-style%20P2P%20Sync%20for%20Windows%20Implementation%20Plan.md#threats-and-mitigations)
against the implementation and record each finding, severity, reproduction,
fix or accepted rationale before closing P5.2.

| Threat or boundary | Primary implementation to inspect | Existing local evidence / open question |
| --- | --- | --- |
| Network eavesdropping and certificate substitution | `src/PeerSync.Net/Quic/`, `src/PeerSync.Net/Tcp/`, `src/PeerSync.Net/Security/PeerHandshake.cs` | P0 QUIC and installed-host peer tests cover authenticated sessions. Independently test a mismatched certificate and protocol downgrade on both transports. |
| Tracker/relay metadata and folder proof | `src/PeerSync.Rendezvous/`, `src/PeerSync.Net/Rendezvous/`, `src/PeerSync.Net/Relay/` | P4 local and installed tests cover presence and relay behavior. A certificate-bound oversized relay request produces a sanitized central ZIP with the session/status and without the relay token or network address; see [local evidence](verification/P4-probe-correlation-2026-10-23.md). A [five-minute physical mobile-hotspot run](verification/P4-native-wan-overlay-isolation-2026-10-24.md) transferred matching native bytes through the relay while PeerSync's Tailscale path was blocked; throughput caps and two-home NAT behavior remain unverified. Independently verify that neither raw server logs nor wire payloads carry folder keys or file bytes. |
| Peer-advertised endpoint and presence fanout abuse | `src/PeerSync.Rendezvous/Tracker/PresenceRegistry.cs`, `src/PeerSync.Service/Hosting/PeerNetworkRuntime.cs` | [Endpoint validation](verification/P4-peer-endpoint-validation-2026-10-24.md) rejects multicast, limited broadcast and reserved targets before publication or dialing; [presence fanout hardening](verification/P4-presence-fanout-2026-10-24.md) coalesces 500-folder bursts into lightweight pending signals and builds current lists when sent. Independently test authenticated malicious announcements, queue saturation, untrusted but syntactically valid unicast targets, and sustained multi-device load on the deployed server. |
| LAN observer | `src/PeerSync.Net/Discovery/LanDiscoveryPacket.cs` and `LanDiscovery.cs` | P2 tests cover rotating HMAC tags. Verify adjacent-hour handling and that raw FolderIds do not appear in announcements. |
| Read-only or malicious peer | `src/PeerSync.Protocol/Signing/SignedRecordFactory.cs`, `src/PeerSync.Engine/Sync/NeededSet.cs`, `src/PeerSync.Engine/Hashing/` | Boundary and Engine tests cover signatures and content hashes. Attempt forged records, malformed signed directory graphs and corrupt block responses. |
| Leaked key, unknown or blocked device | `src/PeerSync.Service/Hosting/PeerNetworkRuntime.cs`, `InstalledFolderHost.cs`, `src/PeerSync.Service/Control/ControlStatusRpc.Mutations.cs` | Installed-host pending/approve/block test passed locally. Repeat on two physical PCs with RequireApproval enabled and check reconnect after block. |
| Compromised writer and hostile paths | `src/PeerSync.Engine/Archive/`, `src/PeerSync.Engine/Native/SafeFileTree.cs`, `src/PeerSync.Core/Paths/PathRules.cs` | Engine and fuzz tests cover archive recovery and path rules. Exercise a destructive signed update and restore visible versions through the installed UI. |
| Private scanner observation | `src/PeerSync.Engine/Scanning/Scanner.Observations.cs`, `src/PeerSync.Engine/Scanning/Scanner.cs` | The disposable stage contains native relative names and metadata in the index directory, outside support bundles. [Local evidence](verification/P5-scanner-observation-staging-2026-10-23.md) covers root binding, active-owner lock and abandoned-stage cleanup. Independently inspect installed ACL inheritance, crash leftovers and any chance that untrusted stage bytes could authorize a deletion. |
| Oversized or flooding input | `src/PeerSync.Protocol/Framing/FrameCodec.cs`, `src/PeerSync.Protocol/Validation/`, `src/PeerSync.Rendezvous/Hosting/RendezvousHost.cs` | Ten-minute fuzz and current 24-hour campaign cover decoder/validation. A hosted 123-request burst hits the 120-token HTTP limit, yields three 429s and one sampled warning while counting each denial; inspect per-IP and per-peer limits under concurrent public-network load. |
| Local control and key disclosure | `src/PeerSync.Service/Control/ControlStatusRpc.cs`, `ControlIdentityInterceptor.cs`, `ControlApiHost.cs`, `src/PeerSync.Crypto/` | Caller identity is enforced before RPC dispatch; `GetFolderKeys` is the explicit audited key-return RPC. Review pipe ACLs and verify denied standard users cannot obtain the key through status, events, dump or error detail. |
| Logs, support bundles and dumps | `src/PeerSync.Core/Diagnostics/`, `installer/Set-WerPolicy.ps1`, `docs/diagnostics.md`, `src/PeerSync.Service/Control/ControlStatusRpc.cs` | Structured events accept metadata fields and the bundle collector excludes keys, FolderIds, arbitrary logs and crash dumps. A verified-pipe integration test audits raw debug output after AddFolder, GetFolderKeys, JoinFolder and DumpIndex; see [control-log evidence](verification/P5-control-key-log-audit-2026-10-23.md). A local scan of three million-file source debug logs found 143,370 parseable events and no fixture path or forbidden identity/key fields; this is a spot check, not proof of absence. A clock-controlled test confirms that the journal's timer removes an idle IP-bearing log after 24 hours without another write; see [local retention evidence](verification/P4-idle-log-retention-2026-10-23.md). Both installers package an owned WER exclusion policy; the [local policy controls](verification/P5-wer-policy-local-2026-10-23.md) and [signed local client upgrade audit](verification/P5-installed-client-archive-2026-10-23.md) pass. The installed probe also screened 843 raw SCM service events after key export and index read, requiring the key-read audit and rejecting key text, FolderId and native path. Later [Server 2025 upgrade](verification/P5-current-source-server2025-upgrade-2026-10-23.md), [Server 2022 client and Server 2025 central uninstall](verification/P3-server2022-uninstall-cycle-2026-10-23.md), and [packaged field collection](verification/P4-field-deployment-collector-2026-10-23.md) verify the installed WER/LocalDumps state and owned-policy cleanup on those guests. Independently inspect other component logs, each deployment host's LocalDumps policy and the [approved dump boundary](proposals/P5-crash-dump-boundary.md) before closing P5.2. |
| Signed update publisher | `installer/Update-Helper.ps1`, `installer/Assert-UpdateSetupSignature.ps1`, `src/PeerSync.Service/Update/` | The local [rotation guard](verification/P5-update-publisher-rotation-local-2026-10-23.md) and [online-chain check](verification/P5-update-signer-chain-local-2026-10-23.md) pass with development signatures. Verify a revoked non-root release certificate, unavailable revocation endpoint, unrelated trusted signer, actual installed update and safe publisher rotation independently before release. |
| Service lifecycle during upgrade and uninstall | `src/PeerSync.Service/Hosting/PeerNetworkRuntime.cs`, `installer/Stop-ServiceAndWait.ps1`, both Inno installer scripts | A physical restart race showed SCM reporting Stopped before the old process released listeners. The [bind-retry repair](verification/P2-listener-bind-retry-local-2026-10-25.md) now has both a native socket-collision regression and a signed installed first-PC SCM check with error 10048 and successful recovery. The [installer guard](verification/P3-installer-service-exit-local-2026-10-25.md) waits for the old service image process to exit. A signed 1.0.25.0 package upgraded both physical clients, including the second PC's legacy unquoted image path, repaired both SCM paths to quoted form, and preserved settings/files with fresh two-way sync. Review timeout, uninspectable processes, path spoofing and recovery during central upgrade and interactive uninstall. |

For the crash-report boundary, run the packaged
[`Audit-CrashPolicy.ps1`](../installer/Audit-CrashPolicy.ps1) on each installed
client and Rendezvous host and retain its JSON with the review. The
[local audit evidence](verification/P5-crash-policy-audit-2026-10-23.md)
verifies the parser and local client state. The later installed-guest checks
above cover those specific hosts; neither local nor VM checks can inspect a
privileged full/live dump on every deployment host.

A current `dotnet list PeerSync.slnx package --vulnerable --include-transitive
--format json --no-restore` audit queried the NuGet.org source after restore.
Its retained report under `artifacts/security/nuget-vulnerable-2026-10-23.json`
lists 35 projects and no reported vulnerable top-level or transitive package.
This is advisory coverage at audit time, not proof that the code or packages
are free of security defects. The independent reviewer should rerun it on the
release candidate and examine the pinned package set.

The P5 fuzz campaign, million-file fresh-peer run, physical two-PC approval,
public update-feed signer and 72-hour soak are
separate open gates. A reviewer should use the exact candidate commit and
record whether those results were available at review time. Do not mark
P5.2 complete from this package alone.
