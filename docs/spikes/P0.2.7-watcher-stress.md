# P0.2.7 — FileSystemWatcher stress and rescan

Question: will a 64 KiB watcher buffer preserve 100,000 rapid creates and
renames, and can a full scan recover if notifications overflow?

`WatcherStress` creates and renames 100,000 empty files in parallel in an
isolated temp directory. It records created/renamed names and Error events,
marks full rescan required on every watcher error, then scans and checks every
expected final name independently of the notifications. Finally it removes
only its own temporary corpus.

2026-10-18 NTFS result: 261 create events, 268 rename events, 6 buffer
overflows, no other watcher errors. The error callback requested rescan. The
actual scan recovered all 100,000 renamed files. Burst plus settle time:
42.287 seconds. Evidence: `artifacts/p0/watcher.stdout.log`.

Decision: watcher events are hints, not the index of record. Keep the required
overflow-triggered full scan and periodic 600-second rescan. This P0 harness
proves the recovery mechanism; it does not claim the future engine watcher
or its debouncer is implemented. Event counts vary by hardware and scheduling.
