# P0.2.6 — Port 99, HTTP/2 + HTTP/3, mutual TLS

Question: can Kestrel carry a bidirectional gRPC stream over exact HTTP/2 and
HTTP/3 on TCP/UDP 99 with the client's self-signed device certificate visible?

`Rendezvous99` runs Kestrel with HTTP1AndHttp2AndHttp3 and TLS 1.3 only, client
certificates required. Each client requests an exact HTTP version; fallback
is disabled. For three request/response pairs, the server derives DeviceId
from the connection's client certificate, and the client compares it with its
own certificate's SPKI hash. The stream completes normally after all replies.

2026-10-18 on the development Windows PC: both exact HTTP/2 and exact HTTP/3
passed on port 99. The certificate was visible in both cases. Evidence:
`artifacts/p0/rendezvous-http2.stdout.log`, `rendezvous-http3.stdout.log`.
No fallback to in-stream device proof was needed on this host.

`windows-2022` hosted VMs and records the actual OS build/runtime. Await those
artifacts before claiming server-version validation. The task remains open;
