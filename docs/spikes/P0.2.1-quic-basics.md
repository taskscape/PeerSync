# P0.2.1 — QUIC and self-signed device certificates

Question: can two Windows processes exchange 1 GiB over PSP ALPN with mutual
certificates and identity derived from the certificate's SPKI?

`build/Run-P0.ps1` starts two `QuicBasics` processes. It tests IPv4 and IPv6,
uses named persisted CNG P-256 keys (Schannel requires persistence), requires
the client certificate, and verifies the receiver's SHA-256 against the sender.
Both sides extract DeviceId from `RemoteCertificate`, never from a message.
All temporary private keys are deleted on normal exit.

2026-10-18, reference development PC: 1,073,741,824 bytes passed on IPv4 at
397.94 MiB/s and IPv6 at 496.34 MiB/s in the recorded local run. These are
loopback results, not 1 Gbit LAN measurements. `artifacts/p0/*quic*.stdout.log`
contains byte counts, time, endpoints and public certificate identities.

Decision: the basic mutual-certificate QUIC approach works on this host.
2026-10-19: two physical devices on different LANs passed 1 GiB over Tailscale
in 220.78 s at 4.64 MiB/s, with a matching receiver journal and verified sender
hash. See [the cross-network evidence](../verification/P0-cross-network-2026-10-19.md).

**Open:** record physical LAN throughput; the overlay run does not supply it.
The entire task remains open until that criterion and the merge/CI rule hold.

Reference: [Microsoft QUIC overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/networking/quic/quic-overview).
