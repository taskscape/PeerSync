Use cases

Where PeerSync earns its place.

PeerSync is for folders that must be the same on more than one Windows machine, where you would rather not route them through a cloud you do not control. Here are the setups it was designed around, with the key and discovery choices for each.

Individual · two machines

Desktop at home, laptop on the road

Keep your working set identical on both machines without a monthly cloud bill or a quota. At home the two PCs talk directly over the LAN at wire speed. Away from home the laptop reaches the desktop through your rendezvous server, hole-punching when it can and relaying when it must.

  • Edit on either side. The newer version wins, the older one lands in the archive instead of being lost.
  • Large files only resend the chunks that changed, which matters on hotel Wi-Fi.
  • The service keeps syncing on the desktop even when nobody is signed in.

Setup recipe

  1. On the desktop: Add folder, then Share and copy the read-write key.
  2. On the laptop: Join with key, choose a local path.
  3. Optional: set your rendezvous server URL in Preferences on both PCs for sync away from home.

Small team · shared project

A shared project folder without a SaaS subscription

A design studio, a research group or a small engineering team shares one project tree. Editors hold the read-write key. Reviewers, clients and build machines get the read-only key: they always see the latest state and can never push changes back by accident.

  • No per-seat pricing and no admin console to keep in sync with your team roster. A key is the invitation.
  • Turn on "Require approval for new devices" and vet each device fingerprint before it joins.
  • Peers swarm chunks from each other, so the fifth person to join does not wait on the first.

Setup recipe

  1. Create the folder on one editor's PC with device approval enabled.
  2. Hand the read-write key to editors and the read-only key to everyone else, out of band.
  3. Approve each new device from Pending devices as it appears.
  4. Rotate access by creating a new folder and re-sharing when someone leaves.

One-way mirror · trusted PC

A live off-site copy on a machine you trust

Mirror your important folders to a PC at a family member's house, a second office or a server in the next building. Give that machine the read-only key: it receives every change but can never write back, so a mistake there stays there.

  • The archive on the receiving side keeps deleted and replaced files for 30 days, a safety net against ransomware or an accidental mass delete on the source.
  • Continuous, not nightly. Changes stream as they happen, with a periodic rescan to catch what the watcher missed.
  • Traffic is encrypted end to end even when it crosses a relay.

Untrusted, encrypted-only peers that store ciphertext without ever holding a readable key are planned for a later phase. Today the receiving PC must be one you trust with the contents.

Setup recipe

  1. Add the source folder on your main PC.
  2. Join on the mirror PC with the read-only key.
  3. Raise the archive retention in Folder settings on the mirror if you want a longer safety net.
  4. Peers apart? Point both at your rendezvous server.

Distribution · one source, many receivers

Pushing builds, datasets and media to a fleet

A CI machine, a render farm or a content team produces large artifacts that many machines need. Publish from one read-write folder and let every receiver join read-only. Receivers fetch chunks from each other as well as from the source, so the source's uplink stops being the bottleneck.

  • Content-defined chunking means a rebuilt installer or re-exported video reuses every unchanged block.
  • Signed indexes mean a receiver cannot be fed a tampered artifact by another receiver.
  • Script it: psp add and psp join slot into provisioning without the dashboard.

Setup recipe

  1. psp add D:\Artifacts on the publishing machine; export the read-only key.
  2. In your provisioning script on each receiver: psp join <RO key> C:\Artifacts.
  3. Add predefined hosts for the publisher's address when LAN discovery does not reach every subnet.

Organization · branch offices

Branch offices with your own rendezvous server

Several sites behind their own NATs need to share folders, and the data must not leave the organization. Run the rendezvous service on one Windows Server you control. It introduces peers to each other, helps them hole-punch, and relays opaque encrypted traffic when a direct path is impossible. It never holds a key or a readable file.

  • One service, one port (TCP and UDP 99), one TLS certificate. Installer, firewall rules and renewal hook included.
  • Health checks, structured logs and aggregate OpenTelemetry counters for your monitoring, with no IPs or folder IDs in the event log.
  • Within each site, peers still talk directly over the LAN. The server only matters across sites.

Setup recipe

  1. Install the Rendezvous package on a Windows Server with a public certificate for its hostname.
  2. Open TCP and UDP port 99; verify from outside with psp probe host:99.
  3. Set the rendezvous URL in client Preferences or by policy.
  4. Collect diagnostics bundles from server and clients when something misbehaves.

Isolated networks · labs and workshops

LAN-only sync in air-gapped or offline environments

Measurement rigs, workshop PCs, classroom labs or a studio network with no internet access. PeerSync needs no server and no connectivity beyond the local segment. Peers find each other by multicast and sync over encrypted QUIC exactly as they would anywhere else.

  • No license check, no activation, nothing that phones home. It simply works offline.
  • Encryption stays on even on an isolated LAN, and discovery tags rotate hourly so a rogue device learns nothing from listening.
  • Disable tracker and relay per folder in Folder settings so nothing ever tries to leave the segment.

Setup recipe

  1. Install the client on every machine from the offline installer.
  2. Add the folder on one PC, join the rest with its key.
  3. In Folder settings, keep LAN discovery on and switch tracker and relay off.

Not a fit, yet

PeerSync is an experimental preview and deliberately narrow. It is not the right tool today if you need:

  • Mobile apps, a web interface or anything other than Windows 11 and Windows Server 2022 or newer.
  • Syncing of NTFS permissions, alternate data streams, symlinks or junctions. They are recorded, not followed.
  • Files held open with exclusive locks, such as live database files.
  • Encrypted-only, untrusted storage peers and on-demand placeholders. Both are planned for later phases.
  • A tool that has passed public beta. PeerSync's LAN and WAN release gates are still open.
