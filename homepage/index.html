Peer-to-peer folder sync for Windows

Your folders, in sync.
No cloud in the middle.

PeerSync keeps chosen folders identical across your Windows PCs, device to device. A folder key is the only thing you share. Files travel encrypted and signed over your LAN or across the internet, and never pass through anyone's server in readable form.

Why PeerSync

Built like infrastructure, not like a tray toy.

A Windows service does the work. A small dashboard and a CLI control it. Everything in between is designed so that a stolen laptop, a nosy network or a compromised relay gives an attacker as little as possible.

Keys, not accounts

Every folder has one random read-write key. A read-only key and an encrypted-peer key are derived from it one way, never back. Whoever holds a key has exactly that level of access, nothing more.

RW → RO → F · HKDF-SHA256 · CRC checksum

Finds peers wherever they are

LAN multicast with hourly-rotating tags so observers cannot track your folders. A tracker for peers across the internet. Fixed hosts when you know the address. A relay only when nothing else works.

LAN · tracker · predefined hosts · relay

QUIC first, TCP as fallback

QUIC gives encryption, multiplexed streams and UDP hole punching in one in-box Windows stack. When UDP is blocked, PeerSync falls back to TCP with TLS 1.3, and then to the relay.

System.Net.Quic · MsQuic · SslStream

Only changed blocks travel

Files are cut into content-defined chunks and hashed with BLAKE3. Insert a paragraph at the top of a document and only the chunks around it move, not the whole file. Peers swarm chunks from each other.

FastCDC · BLAKE3 · block-level swarming

Every change is signed

Each change record carries an Ed25519 signature derived from the read-write key. Read-only peers verify but cannot sign, so a tampered read-only device can't inject anything into your folder.

Ed25519 · pinned device certificates

Nothing is lost silently

When two devices edit the same file, the newer version wins and the other goes to the archive instead of vanishing. Deleted and overwritten files stay restorable for 30 days.

.psp\archive · version vectors · restore

A real Windows service

The engine runs as a service under its own virtual account, so folders keep syncing when nobody is signed in. A WPF dashboard and tray icon give you status, pause and resume, share keys and pending devices.

NT SERVICE\PeerSync · dashboard · tray

Your own rendezvous server

One optional Windows Server component does discovery and relays opaque, end-to-end encrypted traffic when peers can't connect directly. It never receives folder keys or plaintext files. LAN-only sync needs no server at all.

tracker + relay · one port · self-hosted

Diagnostics that respect privacy

One command collects a sanitized support bundle: structured events, timings and error codes, with network addresses, paths, keys and file contents left out by default. Share it without a second thought.

psp diagnostics · 24-hour window · no secrets

Three keys, three levels of trust

All three derive from one 32-byte secret. The derivation only runs forward: a read-only key can never recover the read-write key.

KeyWho holds itGrants
A…Read-write devicesSign changes, read, decrypt
B…Read-only devicesVerify, read, decrypt; local edits never leave
F…Untrusted backup devices (planned)Store and seed ciphertext only
Anatomy of a key
A7XQ4M2KJ3RWH3TBN5CYD6FGV6LPS2ZA4EU7JK3MQ5RT5WX2HN4BC6D
  • A  the access type: read-write
  • 52 Base32 symbols: 32 random bytes from the OS generator
  • 6D  a checksum that rejects any single mistyped symbol

Case, spaces and dashes are ignored on paste. Key text is never written to logs, and key objects redact themselves when printed.

Security model

Three things keep your data yours.

Holding a folder key. TLS 1.3 between pinned device certificates. Signed change records. Everything else is a consequence of those three.

The rendezvous server never sees a key or a byte of file content. Self-host it, and there is no third party left at all.
Someone sniffing the networkEvery byte runs over TLS 1.3, on the LAN too. There is no "trusted network" switch to leave on by accident.
The tracker or relay operatorSees opaque folder and device IDs, addresses and volume. Cannot join a folder and cannot read what it relays.
A device on the same LANDiscovery packets carry hourly-rotating HMAC tags, not folder IDs, so a bystander cannot track which folders you sync.
A man in the middleThe folder proof is bound to both device certificates. Each folder pins a peer's identity on first contact and warns if it changes.
A tampered read-only peerIt holds no signing key, so read-write peers drop anything it tries to push. Data it serves must match signed chunk hashes.
Hostile file paths and floodsRecords with traversal, UNC paths, reserved names or alternate streams are rejected and fuzz-tested. Frames, batches and per-peer requests are capped.

Command line

Scriptable from day one.

Everything the dashboard shows, the psp CLI prints. Check status from a remote shell, add folders in a provisioning script, probe your server, or collect a sanitized bundle for a bug report.

psp statusFolders, peers, transfer state and clock warnings
psp add D:\ProjectsCreate a folder and its keys
psp join <key> C:\Sync\ProjectsJoin with a read-write or read-only key
psp probe sync.example.com:99Verify TCP and UDP reachability of your rendezvous server
psp diagnostics --output bundle.zipSanitized support bundle, no keys, paths or addresses

Get started

Two installers. Two PCs. Ten minutes.

Install on PC A, add a folder, copy its key. Install on PC B, join with that key. Create a file on either side and watch it appear on the other. That is the whole onboarding.

Download from GitHub Releases Read the two-PC guide
Experimental preview. PeerSync has not yet passed its LAN beta, WAN beta or 1.0 release gates. Packages are signed with a development certificate. Try it on disposable test folders and keep backups of anything you care about.

What you need

  • Windows 11, or Windows Server 2022 or newer
  • x64 or Arm64. The installer bundles the runtime.
  • Two PCs on one LAN, or your own rendezvous server on TCP/UDP port 99 for peers apart
  • No account, no subscription, no telemetry phoning home

Want to host discovery and relay for your own team? The rendezvous operations guide covers certificates, firewall rules and probes.
